## 1. 覆盖目标与状态口径

“全品类”指持续扩展硬件类别、模型架构、模态和任务的覆盖，不限定为某个厂商或 GGUF 文本模型。下列名称是代表例子，不是穷尽所有 SKU/权重的兼容声明，也不承诺任意设备能运行任意模型。设备容量、算子、驱动、模型接口与许可均可能限制具体组合。

硬件覆盖目标两种模式相同；模型加载、执行及资源设施共用，生成、决策及其他任务的适配与验收分别记录。**全品类模型覆盖属于主线，Reflex 的模型范围是按决策适用性选择的子集。** 因果语言模型、具备理解/分类/评分能力的多模态或任务模型可以进入候选；纯图像/视频/音频合成模型不纳入 Reflex 常规兼容目标，不要求为了“兼容”强加评估器、训练新头或另跑完整生成。仅完成生成不能继承为 Reflex 支持。

模型记录先区分“纳入 Reflex 目标 / 可选评估 / 不适用或不纳入 / 独立研究”，再记录目标内操作的实现/验证状态。不纳入不是待完成的适配缺口，也不等于数学上永远不能改作分类；研究例外见 4.1。目标内模型缺少对应实现才标记未适配，不把所有主线模型自动加入 Reflex 待办。

| 记录维度 | 含义与证据要求 |
|---|---|
| 长期覆盖目标 | 用户要求纳入路线；不代表已有适配代码、可执行候选或性能保证 |
| 当前已实现 | 有具体 Wllm 入口/实现及限制；实验入口也可已实现，但不等于通过采用门槛 |
| 已验证 | 附报告、构建/模型身份、设备/系统/驱动、配置、负载、日期与检查范围；构建、功能、数值、任务质量、资源、稳定性分别标记未测/通过/失败及条件 |
| 已测收益 | 正确性、质量及资源准入通过后，有受控重复对照与完整成本；单次诊断计时不属于此类 |
| 研究候选／性能预期 | 分别记录待完成条件、估算假设和采用门槛；外部文档或作者成绩不进入 Wllm 已验证栏 |

这些维度不能压成一个“支持”勾选。例如 Vulkan 实验入口已实现但数值门槛失败；CPU 路径有功能验证但完整质量/性能矩阵未完成。资源预算模拟、设备枚举、上游支持、编译成功和实际设备执行分别记账。具体支持键为：硬件/系统/驱动 × 后端及版本 × 模型/权重/适配器摘要 × 精度 × 模式/操作 × 配置与负载。

## 3. 硬件覆盖清单

优先级为用户指定的 P1 最高、P2 次之、P3 后期完善，见第 5 节；各行均为长期目标，当前状态以第 2 节为准。主线与 Reflex 使用同一硬件清单，但分别验收其操作。后端名称只是研究入口，不代表其任一版本支持该行全部型号、精度或操作。

| 编号 | 类别与代表硬件 | 主线与 Reflex 共用的适配方向 | 默认优先级 |
|---|---|---|---|
| H01 | x86：Intel/AMD 桌面、笔记本、工作站、服务器 CPU | 基础指令到 AVX2、AVX-512、AMX 分档；按型号/OS/算子验证，低指令集设备不被长期目标排除 | P1 |
| H02 | ARM：Apple Silicon、Snapdragon、Arm 服务器、树莓派等 | ARM CPU、NEON/其他扩展、线程/内存及工具链；Apple CPU 与 GPU/NPU 独立登记 | P3 |
| H03 | RISC-V、LoongArch、POWER、IBM Z 等 CPU | 可移植实现、工具链、指令优化及状态读写；未取得设备时保留缺口 | P3 |
| H04 | NVIDIA GeForce、工作站、数据中心 GPU | CUDA 等可选路径，显存/驱动/算子与放置分别验证；不是全项目运行前提 | P1 |
| H05 | AMD Radeon 核显/独显、工作站 GPU、Instinct | Vulkan、HIP/ROCm 等候选；共享内存与独立显存分别预算 | P3 |
| H06 | Intel 核显（含 Iris Xe）、Arc、数据中心 GPU | Vulkan、SYCL、OpenVINO 等入口分别锁版，不互相继承验证 | P1 |
| H07 | Apple Silicon GPU | Metal/MLX 等候选，统一内存去重、编译和状态操作验证 | P3 |
| H08 | Adreno、Mali/Immortalis、Xclipse 等移动 GPU | Vulkan/OpenCL/厂商执行路径与移动资源约束；不能按桌面 GPU 结果验收 | P3 |
| H09 | PC NPU：Intel、AMD XDNA、Qualcomm Hexagon 等 | OpenVINO/QNN/厂商编译接口等候选；按算子/形状/精度及实际放置核对 | P2 |
| H10 | 移动/边缘 NPU：Apple Neural Engine、MediaTek、Samsung、Rockchip、Arm Ethos 等 | Core ML、端侧运行时或厂商接口；GPU 与 NPU 执行要能区分 | P3 |
| H11 | 昇腾、摩尔线程、寒武纪等其他厂商加速器，TPU 类设备 | CANN、MUSA、厂商运行时、XLA/PJRT 等分别研究；没有可用接口时明确未适配 | P3 |
| H12 | FPGA、DSP、嵌入式 AI ASIC | 专用编译/执行适配器，评估模型转换与读出接口 | P3 |
| H13 | 多设备：CPU＋GPU/NPU、多 GPU、异构 GPU、多机 | 放置、搬运、同步、状态及取消；先单机后多机、先同类后异构；统一账本不等于所有设备同时执行 | P2；依赖设备未适配则保留该组合缺口 |
| H14 | DDR/LPDDR、统一内存、GDDR/HBM；NVMe/SATA SSD、HDD | 加载、缓存、RAM/显存/存储分层；HDD 可作容量路径，不预设可用响应或提速；共享容量不重复相加 | P2；现有资源准入维护是所有实验的前置 |

设备形态覆盖低配电脑、普通电脑、工作站、服务器、手机、开发板和嵌入式设备；模型必须符合该设备资源和任务约束。平台单独登记并跟随硬件任务：P1 先做 Windows 与 Linux 的 x86/Intel GPU/NVIDIA GPU 代表组合；P2 补 PC NPU 及协同所必需的平台接口；ARM/macOS 普遍覆盖、Android/iOS 与浏览器 WASM/WebGPU 留 P3。例如某个 PC NPU 需要 ARM 主机时，可先补该组合的必要依赖，不将全 ARM 类别整体提升优先级。操作系统、浏览器 API 和硬件不是同一个维度，Windows 编译成功不能替代其他平台执行验收。

### 4.1 生图、图像判断与快速决策的边界

普通扩散生图模型的去噪网络接收带噪样本、时间步与条件并输出样本形状的张量，不能把该输出直接解释为语言候选标签分数，见 [Diffusers 条件 UNet 接口](https://huggingface.co/docs/diffusers/api/models/unet2d-cond)。仅把生图步数截短也不会自动得到可靠的判断头；自回归图像 token 同样不自动具有语义选项评分能力。若某个统一理解/生成模型另具理解或分类接口，应按该具体接口评估，而不是按“生图模型”名称一概排除或纳入。

图像快速选择是另一个任务。例如输入一张图，在“猫/狗”描述间选择，可研究已训练图文对齐的分类/匹配模型；[Transformers 零样本图像分类示例](https://huggingface.co/docs/transformers/en/tasks/zero_shot_image_classification)用 CLIP 的图文分数比较候选。它不要求先生成图片，分数也不是通用推理正确率。Wllm 尚未集成或实测，是否快及质量是否足够仍需对应设备和负载验证；不能把这种评估器的判断能力记到生图主干名下。

生图模型并非绝对不能用于判断：[Diffusion Classifier（ICCV 2023）](https://arxiv.org/html/2303.16203v3)在已有输入图像上，按类别条件比较多个时间步/噪声样本的预测误差，不需额外训练即可开展特定零样本分类。朴素计算量为类别数 × 噪声/时间步采样数次模型评估，作者另作候选淘汰；这不是一次输出 logits 的决策，也不等于生成阶段跑完整条去噪链。能分类不证明快速或通用推理，不能外推到所有扩散/流匹配模型。本项目仅记录外部研究事实，没有运行该方法，也不将其列为 Reflex 必做适配或速度承诺。

另行记录以下维度，不能用一种格式或一个示例替代覆盖：

| 维度 | 长期登记范围与规则 |
|---|---|
| 参数与资源 | 微型到超大型；记录总参数、MoE 激活参数、权重文件、状态与运行峰值。无固定可运行参数上限承诺 |
| 权重与适配 | Base/Instruct、蒸馏、量化、LoRA/其他适配器；绑定适配器组合及许可。支持加载不包括本项目训练能力承诺 |
| 数值 | FP32/BF16/FP16、FP8、INT8/INT4、其他低比特及混合精度；分别核对权重/激活/累加/状态。当前默认不变，转换后重新建质量参照 |
| 载体 | GGUF、Safetensors＋模型配置、ONNX、可信来源的框架权重，以及 OpenVINO/Core ML/MLX/TensorRT/ExecuTorch 等对应工件；有的属于框架或编译产物，不能按后缀猜测可执行能力 |
| 可获得性 | 可获取且许可允许的权重进入本地适配；只有远程 API 的模型另列服务接入，不计入本地硬件/模型执行覆盖。未来接入须明确数据去向与用户配置，不能静默转远程 |

## 5. 适配优先级与进入条件

以下三档严格按 2026-10-23 用户指定排序：硬件两种模式共用，模型按主线全品类与 Reflex 适用子集分别推进。档内按已有设备、复用程度、正确性依赖和验证成本选择有限组合，不按厂商声称的 TOPS 排序；Intel GPU 与 NVIDIA GPU 同为最高档，不因本机只有 Intel 而把 NVIDIA 降档。它是计划，不是完成日期或加速承诺。正确性/质量/资源是各档准入条件，不另设一个阻塞所有适配的 P0 阶段；不要求穷尽一个档位才能准备无依赖的下一档。没有设备或模型时保留缺口，不能用模拟完成验收，也不自动购置/下载。

| 顺序 | 共用基座／硬件工作 | 主线任务 | Reflex 任务 | 对应现有任务与退出条件 |
|---|---|---|---|---|
| P1：最高 | H01 x86 CPU、H06 Intel GPU、H04 NVIDIA GPU；能力登记/接口和当前基线补证；分别建 CPU/Intel/NVIDIA 后端路径 | M01 通用 Dense、M02 MoE、M03 推理、M04 代码；当前 Qwen 继续补证，新增完整注意力 Dense 与一个资源可行 MoE 代表，再扩展各任务；推理/代码优先复用已适配架构 | 优先补 E3-07A 代表任务、标签/顺序扰动、未知类、对照与延迟；在各新模型/后端上验候选读出；完整状态正确后才复用，不继承生成验收 | E2-01/04/05/06、E3-07A–F、E4-08、E5-06/07/08/09；资源最小子集随适配完成；失败 GPU 不阻塞其他独立组合，NVIDIA 不依赖 Iris Xe 修复 |
| P2：次之 | H09 PC NPU、H14 内存与存储分层、H13 多设备协同；先单机协同、再多机与复杂异构，各组合受依赖设备限制 | M11 图文/OCR/文档、M12 视频理解、M13 语音/音频、M14 全模态、M15 图像/视频/音频生成、M16 视觉及其他任务；每类先做一个代表流水线 | 仅选择其中理解/分类/匹配/评分适用任务；纯生图/生视频/音频合成不进入 Reflex 常规待办，不以额外评估器补齐覆盖；多模态协议另版本化 | E4-01–07、E5-06/08/09、E3-02/03；MoE 代表加载/完整路由属 P1，存储卸载/专家分层属此档，不将完整容量线作为首个 MoE 适配前提 |
| P3：后期完善 | H02 ARM 普遍覆盖、H03 其他 CPU、H05 AMD GPU、H07 Apple GPU、H08 移动 GPU、H10 移动/边缘 NPU、H11 其他加速器/TPU、H12 专用设备，以及其平台 | M05 独立 SSM/RNN/混合架构扩展、M06 encoder-decoder、M07 encoder/分类/掩码、M08 向量、M09 重排/奖励、M10 专用决策模型 | 对应专用读出与评分；不适用的直接 logits 操作明确列出，不由相似接口推断支持 | E5-07–09、E4-08；先有可用接口、代表设备/工件与质量参照，再扩大覆盖；优先任务必要依赖可提前补最小子集 |

同档不同类别不要求一类全部完成才开始另一类。硬件与模型是两个独立排序轴：例如 P2 图文模型先在 P1 x86/Intel/NVIDIA 上适配，不必等待移动 GPU；P2 多设备协同先用已适配设备，不借机将所有 P3 硬件整体前移。优先模型包含混合状态、编码器或其他基础组件时，所需最小支持随该模型完成，不把维护现有 Qwen 状态降为后期，也不等于提前完成整类独立模型。文本编码器 M07 与视觉任务 M16 分别按各自类别登记，避免借交叉标签改写用户排序。

E3-07E 校准/回退可在稳定基线上按任务需要准备，不必等待所有最高档硬件完成。新模型/后端适配与失败 CPU 重排、Vulkan 修复、MTP 独立推进；缓存需要对应模型和后端的完整状态能力。每轮只选有限组合，新硬件与新模型尽量分步引入，以定位差异。

## 6. 设计约束与逐项验收

共享基座负责模型/设备身份、配置、生命周期、资源与能力查询、执行调度、取消/超时和计量；模型适配器负责计算图、预处理、分词/模板、状态及输出；任务适配器负责生成、向量、重排或 Reflex 读出。执行可复用多个专长引擎，不要求所有模型迁入 llama.cpp/ggml。具体接口尚未实现，职责见[架构设计](architecture.md#32-全品类适配边界后续设计)；实施拆分见[计划](implementation-plan.md#86-全品类覆盖的适配任务2026-10-23)。

Reflex 适配记录必须先包含模型/任务是否纳入，再记录输入模态、输出头、标签或候选编码、前向/分支次数、原始分数与归一化、校准数据/版本、拒答和回退条件。向量相似度、奖励值、原生分类概率和词表 softmax 不互称等价置信度；新策略不能静默替换现有读出。请求不适用或未实现的决策操作时明确报错，不能暗中切模型、调用远程、生成答案或添加评估器。未来若另行选择组合评估流程，需明确范围、登记全部模型/额外成本/端到端质量；它不是纯生成模型进入 Reflex 的兼容义务。

新增组合至少检查：工件/许可/工具链 → 元数据/算子与资源可行性 → 预处理和功能 → 对应数值/任务质量 → 状态及错误/取消/释放 → 冷暖/编译/加载/全请求资源 → 受控重复性能。普通生成、候选打分、前缀保存/恢复、批量、放置和回滚分别登记；不适用项注明原因。新模型的数值参照与任务阈值在实验前确定，不把当前 Qwen 的张量精度或 logits 阈值机械套到所有架构。

保留当前 Qwen3.5 Q4_K_M、默认 16384、F16 KV/F32 循环状态及普通生成的思考/采样语义；用户未允许时不换模型、降精度、缩短上下文、丢帧/裁音频或改变任务。Reflex 与完整思考输出方式不同，质量等价须独立证明。“覆盖”“可运行”“满足等待要求”“有净加速”分开记录；不要求所有组合都提速，不相乘单项加速倍数。

## 7. 上游研究入口

以下用于发现适配路径，不是 Wllm 兼容承诺；正式接入另锁版本、许可和算子/状态/精度范围。现有引擎锁定版本不因这些链接而改变。

- [llama.cpp](https://github.com/ggml-org/llama.cpp)：文本/多模态及 CPU/GPU 等执行后端研究入口。
- [ONNX Runtime 执行提供程序](https://onnxruntime.ai/docs/execution-providers/)：CPU/GPU/NPU/专用设备图执行接口；各提供程序成熟度和版本不同。
- [ExecuTorch 后端](https://docs.pytorch.org/executorch/stable/backends-overview.html)：端侧、移动及嵌入式部署入口；导出工件须匹配目标后端。
- [Transformers Auto 类](https://huggingface.co/docs/transformers/en/model_doc/auto)：架构及不同任务头的分类参考，不表示 Wllm 可自动加载任意模型。
- [Diffusers](https://huggingface.co/docs/diffusers/index)：图像/视频/音频生成流水线参考。
- [OpenXLA](https://openxla.org/xla)：可扩展编译与设备执行生态参考。

具体参考项目机制与固定版本继续由[统一研究池](engine-references.md)和[Reflex 研究](reflex-research.md)维护；本清单不覆盖既有失败记录或替代历史报告。
