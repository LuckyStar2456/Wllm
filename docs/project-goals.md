### 1.1 最终目标的解释与验收方向

用户于 2026-10-10 明确：最终目标是在不同硬件参数条件下，都能根据用户需求匹配合适的推理策略，包括弱硬件。本机 Qwen3.5 是首个专项验证对象，最终产品需要把专项经验转化为可复用的策略选择能力。

需求先区分硬约束和优化偏好：模型/能力要求、质量、上下文和资源预算限定可行范围；用户对首字、生成、完整回答、参数规模等指标的偏好决定选择方向。精度、模型或上下文可否调整由用户明确配置，不能从“速度优先”或“硬件较弱”推断允许降低要求。

长期策略能力包括：识别硬件与当前可用资源 → 核对模型及后端支持 → 筛除不满足用户硬约束的组合 → 比较执行、放置、缓存、内存分层及允许的模型/精度选项 → 用实际计量校准选择 → 展示生效策略、收益与代价。具体选择算法和运行中调整机制属于后续设计，当前未实现自动匹配。

“最优”指在给定硬件、需求、工作负载和已验证候选范围内寻优；多个目标冲突时展示实测折中，由用户偏好决定。有限测试只能证明候选范围内的结果，不宣称全局或所有输入下的绝对最优。参数规模与任务能力分别评价。

弱硬件验收应包含可运行配置、用户硬约束保持、全流程延迟与内存、资源不足解释，以及可复现的策略选择依据。没有可行组合时明确报告，并展示需要用户选择的调整方案；不保证任意硬件都能运行任意模型，不把仅能加载视为可用。当前首版仍按既定策略在资源不足时明确报错。

## 2. A/B/C 哪条路线适合本机优化

以下为工程判断，不是性能实测结论。

| 路线 | 获得第一份优化结果的便利性 | 可深入的空间 | 成本与限制 | Wllm 建议 |
|---|---|---|---|---|
| A：现有引擎封装与参数调优 | 最高，可直接比较线程、批量和设备配置 | 受现有接口与实现限制 | 快速起步；可能无法解决底层热点 | 借助现成能力交付原型，原型后建立调优参照 |
| B：复用基础，修改调度、内存和算子 | 前期工作略多于 A；已有实现可作参照 | 可针对本机和当前模型逐层深入 | 需数值验证、剖析和维护局部改动 | 用户已确认的主线 |
| C：自研核心推理引擎 | 最低，先要完成加载、计算、状态和后端 | 自主性高，但并不自动更快 | 基础能力与正确性工作多，延迟验证收益 | 暂不作为整体路线；后续可局部采用 |

“更方便尽快提速”选 A；结合本机专项优化和掌握核心技术的长期目标，已确定 **B，先复用基础交付原型，再开展 A 类调优和更深层专项优化**。原型完成不要求证明加速或完成所有后端比较。只有发现现有架构确实阻挡重要优化，且收益值得维护成本时，才提出 C 类局部替换。

llama.cpp 已提供线程、批量、GPU 层分配等测试入口，适合作为起点。SYCL 官方文档提供 Windows 构建及 Iris Xe 枚举示例，但不能据此认定本机 Qwen3.5 全部算子可用或快于 CPU/Vulkan。技术依据见[参考研究](engine-references.md)。

## 3. 两条优化线

### 3.1 固定模型的执行优化：原型后的优先方向

固定当前 Qwen3.5 Q4_K_M 权重身份、模板、分词器、上下文预算、思考设置、采样、输出上限及输入工作负载，减少运行开销。优先研究线程和批量、设备放置、减少复制与同步、缓冲区复用和热点算子。

权重精度、计算/累加精度、KV/循环状态精度要分别记录。保留 Q4_K_M 不代表其他精度可以任意降低。后端切换或计算重排不承诺逐 bit 相同，但必须通过预先定义的数值与任务质量检查；不得以“文本通顺”代替正确性证据。

本项目默认所称“不降低质量”，参照的是现有 Q4_K_M 目标及其推理设置，不是尚未建立的 BF16/FP16 原模型质量等价结论。当前 CPU 路径为注意力 KV F16、循环状态 F32。换量化、换模型、裁剪专家或改变思考长度分别评测，不能仅凭参数增加或同种子短输出一致宣称质量保持。

保持当前上下文预算，不等于宣称本机能达到模型标称的最大上下文；实际预算需在基线阶段读取。资源不足时明确报告，不静默截断。

### 3.2 速度与参数规模的用户选择：后续完成

在已验证的模型及配置集合中提供以下模式：

| 模式 | 选择目标 | 必须展示 |
|---|---|---|
| 默认保真优化 | 固定当前模型和精度，选择已验证执行配置 | 各项速度、质量检查、内存和上下文 |
| 速度优先 | 在用户允许的模型与质量范围内改善响应和生成速度 | 是否换模型、参数量、量化及实际质量变化 |
| 大模型优先 | 在资源、等待时间及上下文约束内选择更大参数量模型 | 总参数、MoE 激活参数（如有）、内存与各项延迟 |
| 中间档位 | 从测得的折中配置中选择 | 相对两端的得失、完整配置与可复现数据 |
| 双项改善候选 | 寻找参数量不减且速度提升，或速度不退且参数量增加的方案 | 对应工作负载、质量和资源约束；没有候选时明确说明 |

“参数量”不是权重精度、文件体积或实际能力的替代指标；不同架构、训练和量化的质量必须单独评估。MoE 总参数与每 token 激活参数同时报告。

不能承诺所有参数量之间存在连续档位；档位对应实际存在且验证过的模型及配置。量化切换可能需要另一份模型权重、卸载重载和额外磁盘空间，不能假定任意精度实时切换。

“双项最优”按可执行目标解释为寻找实测候选中的帕累托前沿：在同一约束下，没有另一个候选能在参数规模不减、各项选定速度不退的情况下至少改善一项。用户关注多种速度，因此保留整组指标；不预设单一综合分数或对所有输入都最优的配置。

切换模型、量化或上下文必须由用户配置明确允许。跨模型比较归入产品能力对比，不能作为固定模型的引擎加速证据。

## 4. 当前与后续边界

当前计划聚焦本机、单模型文本推理。首期先交付可运行、可复现、保持既有约束且有数值计量显示的原型，之后按基础优化、专项优化、容量与档位、兼容扩展分级推进。每级围绕有限优化项交付，不以候选池全部研究完成为门槛。命令行实时指标与结束摘要是推荐首个交付形式；可用计量显示是必需能力，图形界面、HTTP 协议和具体用途工作负载尚未冻结。

后续扩展到大小模型、其他架构、其他硬件、多模型调度和可选 wgp 接入。保留适配边界，但不提前实现全部框架。训练、剪枝或蒸馏不会被隐含纳入“模型参数可调”。

更大模型的内存分层与磁盘卸载可以作为容量实验；能加载不等于响应可用，必须记录缺页、I/O、首字、解码与超时表现。首个专项优化不依赖购置新硬件或外部 GPU。

2026-10-17 的研究场景限定为普通电脑、现有 SSD 与软件，不依赖 CUDA。CPU、核显、RAM 与 SSD 的协同属于研究候选；通过 I/O 扩大容量与获得推理加速分别验收。纯磁盘查表或地址驱动执行的取舍见[研究决策记录](engine-references.md#10-普通-ssd查表与地址计算的研究决策2026-10-17)，不将其写成已具备的计算后端。

文档统一使用三类证据：已验证结果必须链接 Wllm 的实际记录并注明范围；研究候选列出未完成条件；性能预期只能是附假设的估算或实验前目标。源码/元数据核实与外部文档支持另行标注，均不能升级为本机性能结果。既有 CPU 实验的 5% 筛选界线不等于用户定义的“明显加速”；具体体验目标尚需结合负载确定，不把讨论中的倍数建议写成已确认需求。
