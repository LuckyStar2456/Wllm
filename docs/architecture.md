# Wllm 架构设计

更新：2026-10-22，按最新优先级实现候选打分快速决策 CPU 显式首版；默认上下文 16K 及此前设计保留。已实现 Windows CPU 文本路径、计量、资源探测/有界诊断，以及可选权重驻留的连续独立请求模式。Vulkan 实验入口尚未通过数值门槛；候选自动回退、前缀缓存、推测与容量扩展仍属后续设计。按已确认 B 主线推进。

## 1. 本机优先的职责划分

```text
使用方：独立命令入口 / 评测工具（服务及 wgp 后续再考虑）
                         ↓
请求与配置：模型、上下文、精度约束、资源预算、用户目标
                         ↓
硬件与策略适配（后续）：资源探测、可行性筛选、需求匹配、实测校准
                         ↓
模型适配：权重身份、分词与模板、计算图、输出与状态定义
                         ↓
运行时：生命周期、执行计划、内存、缓存、取消与超时
                         ↓
计算基础：复用 llama.cpp/ggml + 有证据支持的局部优化
                         ↓
后端候选：CPU / Vulkan / SYCL / OpenVINO 等（逐项筛选验证）

评测与调优：全流程指标 → 正确性筛选 → 对照实验 → 保存配置
```

首期优先交付当前 Qwen3.5 的可运行文本原型：一个可用后端、模型加载、文本生成、中止释放、显式配置，以及实际可用的数值计量显示。计量显示属于最小运行路径，原型即需提供实时状态、速度/耗时/token/内存数值、结束摘要和可保存记录。上图为逐步演进的职责划分，不要求首期完成全部组件与后端；原型后才围绕优化项分级扩展。调优结果绑定本机，后端和模型边界为后续扩展留出接口。

组件化区分前馈计算（Dense/MoE）、序列计算（完整注意力/线性注意力/循环状态）、权重容器、量化和设备后端。组合支持均需实测。

### 1.1 面向不同硬件与用户需求的策略选择（后续设计）

最终覆盖不同资源水平，包括低内存、低算力、仅 CPU 的弱硬件。策略层应读取设备能力、后端支持与实际可用资源，先应用用户硬约束，再比较可执行候选；不得仅凭设备型号套用配置。没有可行候选时返回原因和可选调整，不能自动降低用户要求。

候选包含执行后端、线程/批量、设备放置、加载与缓存、内存分层，以及用户明确允许的模型与精度范围。输出包含生效配置、适用负载、预估/实测指标、选择依据和代价。调优结果绑定硬件、软件/模型版本、资源条件与工作负载；条件变化时重新评估，不直接沿用其他设备的最优结论。运行中调整的时机和状态迁移需另行验证。

这些职责用于后续形成“资源与需求 → 可行策略 → 执行计量 → 校准选择”的闭环。当前仅实现显式配置、基础资源检查和计量，并未具备跨硬件自动匹配能力；先把本机专项实验做成可复用证据，再扩展策略层。

## 2. 配置及用户控制

配置分三层，序列化格式尚未冻结：

- 模型身份：外部权重路径与摘要、版本、总参数及激活参数、量化、分词器和模板。
- 运行条件：上下文、输出上限、思考/采样设置、线程、批量、设备放置、状态及计算精度、内存预算。
- 选择目标：锁定当前模型，或由用户允许在已验证候选中按速度、参数规模及中间偏好选择。

默认锁定 Qwen3.5 Q4_K_M 及原运行语义。用户选择目标不意味着允许自动降低精度、缩短上下文或切换模型；先应用用户允许的范围及硬约束。

配置默认上下文为 16384（2026-10-21 按用户要求从 4K 扩展），支持 `--context` 或配置文件显式调整，输入不截断、生成不滑动上下文。默认进程处理一个请求；`--interactive` 保留模型权重，每次重新创建请求状态、上下文、采样器与计量，不共享聊天历史或 KV/循环状态。错误、取消、超时或退出会话会释放驻留模型，最终释放耗时单列记录。JSON 配置承载采样、分阶段线程、批次、实验开关、超时与记录选项。CPU 权重额外重排缓冲关闭，注意力 KV 使用 F16，循环状态使用 F32，配置记录已分别输出。16K 的注意力 KV 估算为 512MiB，循环状态仍为 50.25MiB，实际分配需另外观测；4K 校准不得直接应用于 16K。

后续档位返回实际模型、参数量、精度、资源、完整速度指标及证据来源，区分预估和实测。不支持的组合给出原因。档位对应离散候选，不是任意改变模型参数量的旋钮。

### 2.1 独立任务分支：候选打分快速决策（CPU 首版）

请求分发已有两条路径：普通生成保持原模板、思考、采样与逐 token 输出；显式 `candidate_score` 校验候选和非思考答案前缀，执行完整 prefill，提取指定位置的候选标签 logits，返回选择或 unknown 拒答并提前结束，不进入生成循环。CLI 为 `--mode candidate_score --candidates FILE`，配置 `inference_mode` 默认 `generate`；首版只支持 CPU、关闭重排。完整协议与证据范围见[候选打分设计](candidate-score-mode.md)。

首版只允许实际答案位置的普通单 token 标签，比较“完整答案前缀+标签”的分词以验证前缀不变，并核对解码字节与 token 唯一性；非法标签在 prefill 前拒绝。复用完整词表投影、检查全部 logits 有限，再做候选内归一化与确定性排序；不跳过主干，不创建采样器。输入、思考模板及候选协议改变后独立评测。16K、Q4_K_M、F16 KV/F32 循环状态不变；生成 token 为 0，决策延迟与选项 ID 单列，解码速度不适用。

可选完整思考回退属于后续能力，要求独立校准和显式策略；快慢模板不同，先重建请求状态，不直接沿用快分支 KV/循环状态。父请求累计两个阶段的时延、内存和失败，使用统一取消及总超时。普通生成、单 token 打分、完整词语评分与推测回滚分别加入后端操作矩阵，已有 GPU 数值失败不能被新模式绕过。

## 3. 模型适配与兼容性

首个对象为现有 Qwen3.5 GGUF 的文本路径，核对权重映射、张量形状、分词、模板、位置编码和状态生命周期。文本验收不覆盖视觉部分。

官方 Qwen3.5-9B 配置包含线性注意力与完整注意力层，因此缓存及推测回滚必须同时处理相应状态，不能将传统 Transformer KV 缓存实现视为完整适配。[官方配置](https://huggingface.co/Qwen/Qwen3.5-9B/blob/main/config.json)

首版已记录原始模型 SHA256 与文本容器 SHA256，适配报告验证 427 个保留主文本张量的类型、形状与字节哈希；容器改名以及视觉/辅助预测张量排除不能作为固定模型加速证据。当前容器不保留 MTP，见 6.1。能力表按“模型版本 × 权重/量化 × 后端 × 操作”区分 unsupported、implemented、validated、benchmarked。枚举 GPU、加载成功或单算子运行不足以标记完整支持。

### 3.1 后端与操作组合的支持记录（后续设计）

每条能力记录绑定后端入口及提交、模型/容器摘要、各张量类型、计算/累加与两类状态精度、物理设备/驱动、系统及工具链。普通前向、完整/部分放置、前缀保存恢复、会话分叉、推测回滚和取消恢复分别标记“未核实 / 上游说明支持 / Wllm 已实现 / 本机已验证 / 本机已测收益 / 不支持”，附来源、日期与限制；不以一行“支持 Q4_K_M”覆盖所有组合。

| 路径 | 当前证据 | 必须独立检查的组合 |
|---|---|---|
| 当前 CPU | 已有普通文本推理与独立请求驻留验收；新增候选单 token 打分的有界检查见[本轮报告](../reports/candidate-score-validation.md) | 广泛候选任务质量、校准/思考回退及正式性能仍待验收；前缀复用、MTP 与推测回滚未实现 |
| Vulkan | 独立上游和 Wllm 实验构建可运行；2026-10-21 后续 4K 同条件短输入完整词表数值筛选未通过，32 个生成 token 相同；默认仍为 CPU | 量化计算差异定位、修正后数值/质量、循环层与完整放置、状态恢复/回滚、实际峰值及重复性能；失败样本不用于性能采用 |
| SYCL | 上游后端及设备能力可作候选依据，本机运行未验收 | 混合层算子、有效精度、状态操作、放置比例、共享带宽与全程成本 |
| llama.cpp OpenVINO 后端 | 固定上游文档列出 Qwen3.5-9B Q4_K_M；本机未验收 | 运行时张量转换、编译峰值、无状态与状态化执行分别检查；状态化路径的恢复/回滚限制见 R03 |

OpenVINO GenAI 的直接 GGUF 加载与 llama.cpp OpenVINO 后端是不同入口，不能互相转移支持或不支持结论。固定上游文档说明后者 CPU/GPU 默认把 Q5_K/Q6_K 转为 Q8_0_C；保持磁盘 GGUF 不等于保持运行时量化表示。应核实原生路径及数值，不默认启用进一步降为 4-bit 的选项；无法满足固定模型保真条件时单列配置或拒绝。状态化缓存优化、前缀恢复与推测执行必须做组合检查，不能将各自的上游支持相乘。依据见[参考研究 R03](engine-references.md#3-执行编译与加载候选)。

## 4. 执行与本机专项优化

CPU 用作基础参照；Vulkan、SYCL 和 OpenVINO 等按模型、设备及状态操作支持情况筛选。OpenVINO 的图执行路径需单独检查循环状态和回滚限制，不能假定能与所有推测方案组合。不同后端可能在启动、输入处理和解码上各有得失，保留全部指标，不预先宣布唯一赢家。适配依据与限制见[参考研究](engine-references.md)。

原型先采用可运行的基础配置，不等待参数寻优；交付后先测试线程、批量、设备放置及加载策略。仅针对实测热点考虑保持数学语义的融合、布局、缓冲区复用、减少复制和同步、执行计划复用。计算重排先过数值检查；权重、状态或计算精度改变另列实验。

CPU 与核显共享物理内存、带宽及功耗预算。并行可能争用带宽，共享内存也不保证 API 零复制。独显的 PCIe 传输优化不能直接照搬为核显收益。运行时探测指令集和设备能力，不按型号猜测。

每项定制优化可独立关闭，保留上游执行路径作参照。记录上游提交及维护成本；无收益或存在回归时不启用。

### 4.1 原型即具备的计量路径

运行时按请求采集单调时间戳、输入批次进度及目标输出 token 事件，形成统一的计量数据；资源采样器记录推理进程内存及系统可用内存。展示层读取快照，原型以终端实时状态区、结束摘要和结构化记录交付。显示与导出使用同一组字段和计算结果，不能分别计算产生不一致。

计量覆盖加载、输入处理、首 token、持续生成和请求结束；中止、失败也保存已完成计量并注明状态。采集和刷新避免阻塞推理，刷新频率可控；后续优化对照使用相同计量配置。核心数值、单位、窗口与缺失值规则按[实施计划 2.2](implementation-plan.md)执行。完整评测平台可以后续补齐，用户可见的计量路径必须随首版原型一起可用。

## 5. 内存与状态

预算包含权重、量化元数据、KV、循环状态、计算缓冲区、设备及进程开销，并为系统和其他应用预留空间。核显共享容量不能与 RAM 相加。

分开报告工作集、提交内存、系统可用内存及设备分配，避免共享页重复求和。缓存可能降低延迟却增加驻留，必须同时评估。容量不足时明确拒绝、排队或按用户策略卸载空闲模型，不能静默减少上下文。

缓存键绑定模型、量化、模板/分词器、前缀 token、状态格式及必要执行配置。只复用正确边界的 KV/循环状态，不兼容配置使缓存失效。跨请求会话与纯前缀缓存分开管理，取消和超时不能提交未完成状态。

编译缓存、文件系统缓存、模型常驻、前缀缓存分别记录。专家缓存/预取只决定数据何时到达，不改变实际路由或省略必要专家。

### 5.1 最小资源账本与实验准入（部分实现，2026-10-21）

E2 后端实验及 E3 状态实验之前，先落实 E4-01/E5-01 的本机最小子集；完整跨设备自动选择仍在 E5。2026-10-21 新增 `--resources PATH` 和 `scripts/resource_ledger.py`：原生探测不初始化推理后端、不加载模型权重、不读取提示词，只读取必要 GGUF 元数据；记录物理内存、系统提交额度、CPU 能力及 DXGI 接口。Python 工具额外读取 Vulkan UUID 和有效 LUID，把同 UUID 的接口归为一组；仅有型号/PCI vendor-device ID 时不猜测物理身份。原始 DXGI 接口与其预算保留，不累加成多张物理 GPU。

当前 CPU 单序列账本分列映射文件大小、F16 注意力 KV、F32 卷积/循环状态、可选重排副本估算和系统余量。工作区仍用保守的 3GiB 预留，映射驻留量、实际启动/稳态峰值和工作区实测为未知；CPU 基线的前缀缓存、草稿与回滚快照未启用，预算为 0。启动/稳态预算使用同一保守上界，未冒充两个实测峰值。资源工具的 DXGI budget/usage 属于探测进程，不是系统 GPU 空闲量，依据 [Microsoft QueryVideoMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/nf-dxgi1_4-idxgiadapter3-queryvideomemoryinfo)。

`scripts/benchmark.py` 在初始检查、预热和每次样本前重新探测，不满足物理余量/系统提交预算或启用未验收重排时保存 `resource_rejected` 并停止，不生成性能样本。通过准入只表示允许开始采集，不表示已校准峰值或已验证性能。普通推理继续沿用独立的内存拒绝/分页提示策略，补入循环状态估算，不因性能门槛而静默改变模型、上下文或采样。有效带宽、存储 IOPS、其他后端的实际分配与状态操作仍待实施，不能把本轮视为完整 E4/E5。

显式校准路径已实现：`--memory-diagnostic` 在上下文就绪、输入处理结束和上下文释放前读取后端缓冲区，并记录 OS 进程生命期峰值。`process_peak_private_bytes` 来自 Windows `PeakPagefileUsage`，表示进程提交内存峰值，不表示实际磁盘分页字节。完整权重驻留估算仍保留整份文件大小，另加实测进程提交峰值、固定余量与系统预留；不能只取较低的工作集观测。只有显式绑定当前模型、可执行文件、配置/硬件和负载清单的校准能进入基准准入，原生静态账本继续保留，二者分别记录。普通运行、状态快照和 GPU 分配不自动继承 CPU 校准；详见[内存与后端后续报告](../reports/memory-backend-validation.md)。

| 类别 | 计划记录内容与边界 |
|---|---|
| 物理设备 | CPU 指令集/核数、设备 UUID/PCI 标识、驱动和后端；相同设备的不同接口枚举去重。音频加速单元等不能凭名称视为可用 LLM 后端，缺少算子/工具链证据标未知 |
| 容量与额度 | 总 RAM、当前可用 RAM、系统提交量/额度、共享内存及磁盘空间分别记录；本机 Iris Xe 的共享显存不提供独立于 16GB RAM 的额外容量 |
| 启动峰值 | 映射权重、后端副本/重排、图编译临时数据与缓存生成；按同时存活的分配记账，不把所有阶段的峰值简单相加 |
| 持续工作集 | 主权重、量化元数据、注意力 KV、循环状态、计算缓冲、前缀缓存、草稿和回滚快照；共享页去重，磁盘映射大小不等于实际驻留 |
| 系统余量与性能 | 为系统和其他应用预留可配置余量，记录分页/I/O 与失败；有效内存/存储带宽及 IOPS 用代表性访问实测，不能用规格峰值充当测量 |

实验准入先核对硬约束和能力，再估算加载/编译与稳态两个预算，最后用实际峰值和重复全流程测量校准。资源不明或余量不足时标记不具备性能验收条件；不得为完成比较自动关闭其他应用、缩短上下文或降低精度。允许容量实验发生受控读取，不把“提交成功”或“大分页文件”当成驻留或性能保证。探测记录标注时间和来源，瞬时空闲内存不固化为产品常量。

## 6. 推测执行：早期检查，条件成立后实验

独立小模型草稿、提示词查找与 n-gram、MTP、特征草稿、块状及树状推测等路线并列进入 E2 适配筛选，不按项目知名度或用户是否点名决定先后。具体候选及研究证据见[参考研究](engine-references.md)。

统一生命周期为：保存目标状态 → 草稿提议 → 目标批量验证 → 接受合法前缀 → 回滚未接受状态。需要模型匹配、隐藏状态/草稿接口、tokenizer、KV/循环状态保存恢复，以及采样语义检查。

固定 Q4_K_M 目标，不因启用草稿改动其精度或上下文。greedy 一致性、采样分布等价和有限精度下数值接近是不同证据。只验证 greedy 的实现不能悄悄将用户的采样改为 greedy。采样正确性需要核对验证算法并做分布检查，不能只比较同种子输出或主观质量。

测量接受 token 数、草稿时间、目标验证、同步/回滚、额外权重/状态，以及启动、首字、解码、全程净收益。平均每轮接受更多 token 不自动意味着更快。需要重新训练草稿才能实现的研究不隐含纳入本项目训练范围。

## 7. 大模型容量与后续扩展

先实现一次加载一个模型与显式切换，再决定是否多模型常驻。切换记录重载开销、缓存失效和会话不兼容。

张量放置、CPU/核显协同、专家分层、热点驻留、流式读取与状态卸载按统一标准比较，为后续更大模型提供参考；当前 Qwen3.5-9B 的 Dense 路径不能直接套用专家缓存。总参数与激活参数分开统计，不能据激活量计算全部权重容量。

磁盘卸载作为容量实验，报告缺页、I/O、尾延迟和实际可用性。预测未命中时仍加载并计算必要专家；任何近似专家省略或状态丢弃机制均不进入默认保真路径。

具体任务与来源见[实施计划第 8 节](implementation-plan.md#8-剩余任务与参考实现明细)：E4-02–05 负责 MoE 存储、缓存、协同与流式读取，E4-06 为独立 Dense 路径，E4-07 为状态分层。Strata 的 RAM/设备分工、热专家缓存与后续核实的部分 SSD 权重读取路径按版本区分；Colibri 提供按需读取/预取参考。2026-10-17 的资料补充见[参考研究 5.2](engine-references.md#52-strata-资料更新2026-10-17)，不继承其硬件门槛、精度或性能结论；每部分单独适配、验收后再组合。

### 7.1 SSD 容量与速度的成本边界（设计估算，未实测）

对明确的一轮执行，记录必须从物理存储读取的字节 D、实际请求数 Q、代表性访问的有效带宽 B、IOPS I，以及有先后依赖的未命中读取关键路径 L。筛选估算可写为 `T_io ≳ max(D/B, Q/I, L)`；B/I 必须注明访问尺寸、队列深度、缓存与并发条件，这不是由标称 SSD 规格推出的严格实测下界。端到端还包含计算、复制、同步和未隐藏的等待；可重叠部分不能简单相加，也不能假设全部被隐藏。

- Dense：普通单 token 前向按实际必读张量集合及稳定驻留部分估算 D，不用整个 GGUF 文件大小代替必读权重，也不把 MoE 激活稀疏性套过来。大部分必读权重每步重新读取时，SSD 可扩大容量但可能显著拖慢生成。上述口径只针对该执行方式，批量验证/多 token 复用需按实际接受输出重新摊销，不作为所有算法的绝对上限。
- MoE：先保证路由完整，再记录需求字节的缓存命中率（按字节加权）、实际 SSD 字节/接受输出 token、换入/淘汰、有效/浪费预取和尾延迟。单纯专家个数命中率会忽略大小与访问差异；每层路由依赖限制可提前读取范围。多盘并发用共享总线下的实测总带宽，不能直接相加标称值。
- 缓存：逻辑读取、系统文件缓存命中和真正的磁盘 I/O 分列，mmap 不等于数据已驻留；进程重启不等于冷盘。比较无预取、正确按需读取与有界预取，不能以后台预热隐藏启动成本。

每项输出两份判断：在固定预算下能否完成原本放不下的模型，以及相对明确定义参照是否降低全流程延迟。只有前者成立时标记“容量改善”；计算加速、I/O 重叠与前缀避免重算分别归因。性能预测给出假设和范围，用实测校准后才可作为选择依据。

其他硬件、其他架构、视觉、并发调度及 wgp 接入后续单独验收。研究已有框架不等于全部集成为依赖；格式转换和量化差异先核对，再决定能否同组比较。
