# Reflex：候选打分快速决策模式（System 1 分支）

2026-10-24：共用 CPU 基座新增默认关闭的单条前缀快照实验，`--prefix-cache-mib N`；候选预算和复用 token 单列，但模型恢复/数值/隔离与性能未验收，用户选择本轮保留候选。下面原有“前缀复用待研究”指采用/完整验收仍待完成，不将实验实现等同已验证缓存，见[报告](../reports/prefix-cache-candidate.md)。

名称为 **Wllm Reflex**，简称 **Reflex（反射决策）**。它作为 Wllm 内部模式，与普通生成共用同一仓库和推理引擎基座，按同一路线演进。当前 CLI 继续使用 `system_one` / `candidate_score`；名称更新不改变运行协议、模型、默认生成设置或既有验收结果。

文档更新：2026-10-23，补充[全品类覆盖与三档优先级](hardware-model-coverage.md)，未改实现。2026-10-22 首版状态仍为：**CPU 显式单 token 打分已实现；自动回退、多 token 评分及广泛任务质量/性能验收仍未完成**。默认模型与普通生成行为不变；本机有界证据见[验收报告](../reports/candidate-score-validation.md)。

长期 Reflex 与主线覆盖相同硬件类别，**不要求兼容全部模型**。模型只选择适用候选决策/分类/评分的子集，沿用用户指定的主线档位：Dense/MoE/推理/代码优先，多模态理解及其他适用任务次之；纯生图/生视频/音频合成不纳入常规兼容，不要求为了兼容附加评估器或训练新头。这里的单 token 算法只是现有读出方式；未来可选分类头、条件序列、向量/重排等需各自适配，不能沿用词表 softmax 或继承生成验收。先记录是否纳入，目标内缺实现才标未适配；当前 CPU、文本、单 token 和原协议限制不因长期目标改变。生图模型的分类研究例外与成本边界见[说明](hardware-model-coverage.md#41-生图图像判断与快速决策的边界)。

## 1. 定位与证据

用户提出：将输入上下文处理到答案位置后，读取 logits，比较有限选项并直接返回决策，作为通用大模型的独立推理分支。设计名称为“候选打分快速决策模式”，规划标识 `candidate_score`；System 1 表示快速直接判断的使用方式，不表示改变模型架构、具有人类认知机制或一项已证明原创的算法。它也不等同于 chat 的 system 角色，仅添加 system 提示词不能实现运行时提前结束。

适用任务为意图分类、选择题、动作候选选择和任务路由。调用方提供有限选项及清楚的判断任务；开放式写作、未知答案空间或需要长过程推理的请求继续使用普通生成路径。返回选项只是决策数据，不包含执行该动作的权限或执行结果。

| 证据类型 | 当前状态 |
|---|---|
| 已实现能力 | `candidate_score` 在 CPU 上完成 prefill 后读取完整未采样 logits，比较候选并提前返回；普通生成仍保留原流程。`--logits-file` 依旧是诊断导出，不能单独启用决策模式 |
| 上游接口依据 | [模型输出定义](https://huggingface.co/docs/transformers/main_classes/output#transformers.modeling_outputs.CausalLMOutputWithPast)区分词表 logits 与隐藏状态；[Qwen3.5 非思考模式](https://huggingface.co/Qwen/Qwen3.5-9B#instruct-or-non-thinking-mode)提供 `enable_thinking=False` 的模板配置说明 |
| 有界验证与研究边界 | 本机模板、原始 logits 对照、提前结束、独立请求与取消/超时按验收报告逐项记录；自动门控/完整思考回退仍是研究候选，不能由小样本推导通用准确率 |
| 性能预期 | 可省掉后续文本生成及显式思考 token 的计算；仍需主干前向、输入处理和模型驻留，不承诺准确率保持、绝对延迟或加速倍数 |

与默认保真优化分开记账：固定 Q4_K_M 主权重和当前上下文预算，不意味着取消显式思考与改变输出决策后语义完全不变。用户显式选择此任务模式才采用直接回答模板；普通生成默认思考、采样与停止规则不受影响。无需 MTP、额外草稿模型或新训练。任务编号为 [E3-07](implementation-plan.md#82-e3执行状态与解码专项优化)。

## 2. 输入、输出与模式选择

面向结构化应用新增 `--mode system_one --request-file FILE`，采用 JEV 的 `state + questions` / `answers` 文本格式；仅接受 questions，不接受 ask。它复用本节底层单 token 打分，但自动映射标签，并按 choice/noul/score 返回答案，不要求调用方提供候选标签文件。多题串行、请求状态隔离，confidence 使用官方公式作用于本地分布；详见[协议说明](system-one-protocol.md)和[本机报告](../reports/system-one-validation.md)。旧 candidate_score 协议和 unknown 状态不变。

底层入口为 `--mode candidate_score --candidates FILE`，或 PowerShell 的 `-Mode candidate_score -CandidatesFile FILE`；配置字段 `inference_mode` 可为 `generate`（默认）、`candidate_score` 或 `system_one`，候选文件/结构化请求仍由请求参数提供。其余设计字段按下表区分已实现与后续能力。

| 输入项 | 约定 |
|---|---|
| 模式及模板 | 显式请求 `candidate_score`；固定模板版本 `wllm-candidate-score-v1`，验证实际渲染的非思考答案前缀；`--inspect` 可导出完整前缀、有效 system/user 内容和标签 token 映射 |
| 上下文与问题 | 完整任务输入及明确问题；沿用用户上下文预算（当前默认 16384），不自动截断或缩短 |
| 候选集合 | 至少两个候选，提供稳定 ID、简短标签和选项描述；描述可以多 token，首版真正打分的标签必须在实际答案位置对应一个普通 token |
| 不确定策略 | 已实现 `unknown_id` 指定不确定候选；该候选得分最高时返回 `abstained`。未指定时必须显式声明 `exhaustive: true`，否则启动前拒绝；尚无已校准的得分阈值 |
| 回退策略 | 首版固定 `fallback: disabled`，不自动进入完整思考；校准与显式回退配置属于后续子项，候选文件中不接受未实现的 fallback 字段 |

例如问题为“请把客厅的灯打开”，候选可写成 `A=开灯、B=关灯、C=查询状态、D=无法判断`。A–D 只是示意，必须经实际 tokenizer 和前缀验证后才能作为单 token 标签。

返回结构规划包含：请求 ID、模式/模板版本、结果状态（已选择 / 不确定 / 错误 / 取消 / 超时）、最终分支（快速打分 / 完整思考）、选中候选 ID、各标签 token ID 与原始得分、得分差距、可选候选内归一化分数、回退原因，以及阶段耗时和资源。回退时同时保留快速阶段的候选与最终决策，不能覆盖原分数后伪称一次快速成功。选中 ID 通过调用方映射获取完整选项，不要求模型复述描述。

首版 stdout 每个请求输出一行 JSON，详细指标及诊断走 stderr/JSONL。成功字段包括 `status`、`selected_candidate_id`、`top_candidate_id`、`scores`（含 `token_id`、`logit`、`candidate_normalized_score`）、`logit_margin`、`tie_for_first` 和 `metrics`；`route` 固定为 `fast`。不确定时 `selected_candidate_id` 为 null，最高分不确定项仍保存在 `top_candidate_id`。平局固定按候选输入顺序并明确标记。运行中错误、取消、超时也返回未选中结果；启动前无效参数/候选文件的错误只走 stderr、退出码为 1。取消和超时退出码分别为 130/124，`selected` 与 `abstained` 为正常完成、退出码为 0。

候选文件必须是只含 `candidates` 及可选 `unknown_id`/`exhaustive` 的对象；每项恰含非空字符串 `id`、`label`、`description`，标签拒绝 ASCII 空白/控制字符，再由实际 tokenizer 校验单 token/普通 token 条件。示例见[灯光候选文件](../configs/light-switch.candidates.json)。`--interactive` 可在相同候选集合下连续处理独立问题，保留权重但重建请求状态。

## 3. 单 token 首版执行流程

1. 校验候选 ID/标签唯一、至少两个候选、上下文预算与后端数值支持；空标签、特殊控制 token、重复 token ID 或无法表示为一个 token 的标签明确拒绝。不静默只取首 token，不自动切换更昂贵的完整词语评分。
2. 按已验证的非思考模板构造任务，固定 assistant 的答案起始位置，并核对实际 token 序列。空格、换行、角色分隔符与 `<think>` 边界均影响预测位置，不能直接在 user 文本末尾截取任意 logits。单 token 标签映射及 token/字节边界必须结合真实前缀验证，不能仅对孤立标签 tokenize 后假定等价。
3. 完整执行输入 prefill，取得指定答案位置的、未经采样处理的词表 logits。首版复用现有完整词表输出投影，仅提取候选项；不假定只读几个分数便省掉主干或输出投影计算。
4. 为每个候选取分，按预定确定性规则排序；无需采样或生成选项字符。原始打分不套用生成路径的 temperature、top-k、top-p、重复/存在惩罚；这些设置仍保留在普通生成配置中，并在模式记录里标明本分支不适用。
5. 按任务适用条件和已校准的不确定规则选择、拒答或回退；分数非有限值等运行错误不可包装成低置信度有效选择。取消/超时立即终止，不触发自动重试。
6. 快速路径取得结果后结束请求，不进入自回归生成循环，正确释放请求状态；若权重驻留，只保留原有模型生命周期，不能跨独立请求混用 KV/循环状态。

设候选标签对应 token 为 `t_i`、答案位置 logits 为 `z`，首版选择规则为 `argmax_i z[t_i]`，相同得分按预先固定规则处理并标记平局。候选内归一化可定义为 `q_i = exp(z[t_i] - m) / sum_j exp(z[t_j] - m)`，其中 m 为候选最大得分，使用数值稳定计算。

q 仅表示在给定候选标签之间重新归一化后的相对分数，不是正确率；即使词表中其他 token 得分更高，候选内 q 仍可能非常集中。需要全词表概率或候选总概率质量时，须单独按全词表归一化并记录开销，仍不将其称为校准正确率。

多 token 标签/完整选项的评分留作扩展：使用 `sum_k log P(y_k | x, y_<k)`，需要额外前向或分支批处理，显式定义长度、结束边界及是否归一化；不能把多 token 选项首 token 的分数作为整句概率。该扩展与单 token 路径分别验收，未纳入首版必备实现。

## 4. 快速判断与完整思考回退

首版已实现可审计的显式打分及 unknown 候选拒答；校准和自动回退是后续子项。任务范围检查、候选差距、候选内熵或“无法判断”选项只能作为候选门控信号。模型可能自信出错，因此不能把“差距大”设为通用正确保证，模板或候选集变化也可能令阈值失效。

门控规则用独立校准集选定，在未参与调参的测试集检查选中部分的准确率、覆盖率、拒答率和回退率；阈值绑定任务/模型/模板/标签版本。未取得可接受证据时仅供显式实验，不默认在所有聊天请求间自动分流。调用方未允许降低任务质量时，以该任务的完整思考参照检验要求；不达标则保留参照路径。

回退使用同一原始问题及候选，恢复调用方的完整思考、采样与上下文设置，明确要求返回可映射的选项或不确定。由于快慢模板和前缀不同，第一版重新建立请求状态，不直接复用非思考分支 KV/循环状态；只有共享前缀和状态等价经过验证后才研究复用。不得把已截断的思考内容当作完整推理结果。

一个父请求记录快速阶段、重新准备与完整思考的累计墙钟时间、内存及最终状态，使用统一取消信号和总截止时间。回退造成的重复 prefill、权重生命周期和可能失败都计入总体体验，不只展示成功快速子集的延迟。

## 5. 计量、质量与采用条件

快模式的直接收益假设是减少生成工作，不能作为原生成模式的同语义算子加速。比较任务输入和答案集合一致，分别展示三条路径：完整思考后选择、相同非思考模板下的单标签选择参照、候选 logits 打分；混合回退另外统计。完整思考可能得出不同答案，不能将与非思考参照一致当成与思考质量相当。

| 检查 | 计划验收条件 |
|---|---|
| 模板与数值 | 验证答案位置、标签 token/字节边界、词表索引与完整 logits 对照，覆盖中英文、空白、重复/非法候选、平局、NaN/Inf；沿用既定后端数值门槛 |
| 任务质量 | 分类/路由/选择题含歧义和候选外输入；有标注正确答案，测试标签重映射、选项顺序与措辞变化；报告准确率、分类别表现、覆盖/拒答和错误案例，预先约定采用门槛 |
| 回退质量 | 校准集与测试集分离；分别报告快速接受子集与全部请求结果，检查自信错误、拒答和回退后仍错误的样本；不保证自适应分支无质量损失 |
| 生命周期 | 验证快速结束确实无后续生成计算、独立请求状态隔离、取消/超时/错误与驻留释放；回退不串状态或重置总超时 |
| 性能与资源 | 关闭 logits 文件导出、剖析及内存诊断的正式路径，先过资源准入与数值/质量门槛，再交替重复测量；CPU 首验，未通过数值门槛的 Vulkan 候选不因只比少量标签而绕过检查 |

计量包含启动/加载、模板与 token 化、输入处理、取分/决策、首次决策和整个请求耗时、模型/两类状态内存及工作集/提交量。加载冷暖、权重驻留、前缀复用分别记录。快速请求可以处理大量输入，不能把一整个 prefill 称为“一次 token 计算”。

纯快速路径没有自回归生成 token：生成 token 数为 0，解码 tok/s 标记“不适用”；选中标签和 token ID 另列，不伪造一个已生成 token 或无穷吞吐。重点报告决策延迟、同等资源条件下的决策吞吐，以及准确率与覆盖率的组合；串行延迟测量和并发吞吐实验分开。

成本模型为 `T_fast ≈ T_load + T_template + T_prefill + T_select + T_cleanup`。回退请求按实际发生的两个阶段累计，避免共享加载重复记账；长输入仍受 prefill 限制，权重/主干容量基本需求不因输出变短而消失。只有实测后才能填写收益；不根据省掉的 token 数直接承诺倍数。

## 6. 分步交付与当前边界

本分支属于 E3-07，和 E3-04 推测解码分别实现：前者改变任务的输出决策方式，后者仍需验证和生成目标输出。与前缀缓存、后端或其他机制组合时重新检查模板/状态兼容性并做消融。

1. **文档设计：已完成。** 协议、实现范围和后续能力分别标注。
2. **显式单 token 打分：CPU 首版已实现。** 包含模式分发、模板/标签检查、提前结束、unknown 拒答、计量和状态释放，保留普通生成行为。验证结果以本轮报告为准；不因此宣称广泛任务质量等同完整思考。
3. **校准与完整思考回退：待实施。** 显式模式通过后，才研究门控、整请求预算与分支统计；没有验证的自动路由不进入默认路径。
4. **扩展与组合：待研究。** 多 token 选项评分、前缀复用和其他后端各自过正确性/质量/资源检查，再比较净收益。

本模式只作为新增的可选任务分支，不改变现有 16K 默认上下文、模型权重/精度、普通生成思考设置或当前 GPU 候选状态。首版主动拒绝 GPU 放置及未通过数值门槛的 CPU 重排；下一步任务质量阈值和正式性能对照另行固定。普通运行沿用既有内存检查，资源余量不足的功能诊断不作为正式性能验收。

## 7. 首版运行与复现

```powershell
./scripts/run.ps1 -Mode candidate_score -CandidatesFile configs/light-switch.candidates.json -Prompt '请把客厅的灯打开'
# 同一组候选下连续输入独立问题，空行或 /exit 退出：
./scripts/run.ps1 -Mode candidate_score -CandidatesFile configs/light-switch.candidates.json -Interactive
# 本机构建与有界检查（不构成广泛质量/速度基准）：
./scripts/build.ps1
py -3.11 -B tests/test_candidate_score.py
```

原生命令也可使用 `build/bin/Release/wllm.exe --config configs/local.json --mode candidate_score --candidates configs/light-switch.candidates.json --prompt "Turn the light on"`。结果为请求结束后的 JSON，`metrics.decision_s` 是从请求开始到决策就绪的时间，`candidate_selection_s` 只含取分/选择阶段，`elapsed_s` 还包含请求清理；不要将三个口径混用。请求记录保留原 `thinking` 设置并另列 `effective_thinking: false`、`sampling_applied: false`，普通生成未修改。正式计时不要启用 `--inspect`、`--logits-file`、剖析或内存诊断。

## 7. 参考项目补充设计（2026-10-22）
