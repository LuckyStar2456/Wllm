## 1. 项目目标与技术路线

Wllm 是一个本地推理项目，Reflex 是内部候选决策模式，两者共用仓库、引擎基座和演进路线。主线长期覆盖全品类硬件、模型及任务，包括低内存、低算力和仅 CPU 的弱硬件；在资源与用户要求允许的范围内寻找可用且更优的推理策略，不承诺任意设备运行任意模型。

原定 **B 路线保持：复用 llama.cpp/ggml 等成熟基础，再深入执行调度、状态、内存、设备放置和热点算子优化**。先有可复现的可运行版本，再按瓶颈逐项交付。整体重写引擎不作为当前路线，只有现有接口确实阻挡有证据的重要优化时，才评估局部替换。其他任务可接入合适的执行引擎，不要求全部迁入 ggml；接口扩展尚待实施。

计划有三个独立维度：

| 维度 | 决定什么 | 与其他维度的关系 |
|---|---|---|
| 性能与容量路线 | 在具体设备/模型/负载上优化什么，怎样证明有效 | 基础执行 → 状态/算子/推测专项 → 容量分层 → 组合选择；按依赖和热点进入，不要求穷尽前一步 |
| 硬件与模型覆盖 | 先适配哪些类别与代表组合 | 使用用户 P1/P2/P3 排序；适配完成不等于性能改善，也不替代原优化路线 |
| 模式与任务 | 普通生成、Reflex 或其他任务怎样输出与验收 | 共用设施，任务语义与质量分开检查；不能从一种模式继承另一种的兼容或收益 |

### 1.1 默认约束与用户选项

- 当前基线为本机 Qwen3.5 文本 Q4_K_M、默认 16384 上下文、F16 注意力 KV/F32 循环状态；普通生成的模板、分词、思考、采样、停止和输入内容保持。新模型按其原生任务/状态建立参照，不机械套用 Qwen 的结构和阈值。
- 用户未明确允许时，不换模型、不降精度、不缩短上下文、不关闭思考、不裁剪专家或静默删减模态输入；资源不足明确说明。跨后端不要求逐 bit 一致，但必须通过实验前约定的数值与任务质量门槛。
- “默认保真优化、速度优先、大模型优先、中间档位、参数规模与速度双项改善候选”保留为产品方向。后四者只在实际存在且验证过的配置中选择，改变模型/精度/上下文须在用户允许范围内；当前没有通用自动档位系统。
- 参数量、MoE 激活参数、权重文件和运行峰值分别记录；参数更大不自动等于能力更强。CPU、Intel GPU、NVIDIA GPU 都可优先适配，CUDA 仍只是可选后端，不是全项目运行前提。

### 1.2 Reflex 的范围

Reflex 只选择具备候选判断、分类、匹配或评分适用性的模型/任务子集，**不要求兼容全部模型**。纯生图、生视频和音频合成不纳入常规 Reflex 待办，不要求为了兼容增加评估器或训练新头。不纳入不是未完成缺口；扩散分类的研究例外见[覆盖清单 4.1](hardware-model-coverage.md#41-生图图像判断与快速决策的边界)，不代表快速决策已成立。

当前模式名是 Reflex，运行参数仍为 `candidate_score` / `system_one`。后者保持 `state + questions` 和具名 `answers`，不接受 `ask`。当前是本地文本 JSON 入口，不是 HTTP 服务，不调用远程 Jev，也不授权执行所选择的动作。

| E4-04 | CPU/GPU 专家分工及可验证的重叠 | 待实施，依赖 E4-02 与两侧后端；先串行后重叠，计算/传输/归并/同步分列，核显不照搬独显收益 |
| E4-05 | RAM/SSD 专家流式加载与有界预取 | 待实施，依赖 E4-01/02；预测失败仍完整读取/计算；计实际物理 I/O、等待及浪费预取，不把文件缓存命中当 SSD 带宽 |
| E4-06 | Dense 层/张量流式加载 | 待实施，独立于 MoE 专家线；按实际必读张量/驻留量估算读取，校准带宽/依赖等待，多 token 复用另摊销，不套稀疏专家收益 |
| E4-07 | KV/循环状态分层与读取/重算比较 | 待实施；依赖对应状态接口和完整语义，保持精度/上下文/恢复，记录容量、搬运和全程成本 |
| E4-08 | 模型/精度选项、速度/大模型/中间档位及双项改善候选 | 待实施；依赖账本与对应模型/后端实际支持；用户允许后显式切换，展示质量/全部速度/资源/重载和失效成本 |

模型选择与容量机制分开排期：**MoE 代表模型加载/完整路由属于 P1；专家缓存、卸载和多设备协同属于 P2**，不要求先完成整条分层线才能支持首个 MoE。E4-01 最小预算是所有实验的准入前置，不因完整内存分层排 P2 而推迟基本资源检查。

存储先比较全驻留、部分驻留与仅 CPU/容量受限条件。先用小模型/受控预算验证逻辑，再做真实设备与工件验收；模拟预算不能冒充实机弱硬件结果。SSD/HDD 提供容量与搬运，不能仅靠并行 I/O 宣称获得额外算力；Dense 每步大量重新读取可能拖慢生成。按实际字节、请求、有效带宽/IOPS、依赖等待和重叠测全程，不能相加标称带宽或隐藏预热成本。每项分别给出容量是否扩大、是否完成任务、是否满足等待要求、是否有净提速四项结论。

## 6. 硬件与模型适配优先级

以下是用户已确认的覆盖排序，独立于 E2–E5 的优化任务编号。完整型号/家族、格式/精度维度与适用性见[覆盖清单](hardware-model-coverage.md)。

| 档位 | 硬件 | 主线模型 | Reflex 范围 |
|---|---|---|---|
| P1 最高 | x86 CPU、Intel GPU、NVIDIA GPU | 通用 Dense、MoE、推理、代码 | 其中适用候选判断的模型/任务；质量单独验证，不继承生成验收 |
| P2 次之 | PC NPU、内存与存储层级、多设备协同 | 图文/OCR/文档、视频理解、语音/音频、全模态、图像/视频/音频生成、视觉及其他任务 | 只选理解/分类/匹配/评分适用子集；纯生成不纳入常规兼容 |
| P3 后期完善 | ARM、其他 CPU 架构、AMD/Apple/移动 GPU、其他 NPU、其他厂商加速器/TPU、FPGA/DSP/ASIC 等 | 独立 SSM/RNN/混合架构扩展、encoder-decoder、encoder/分类/掩码、向量、重排/奖励、专用决策模型 | 适用性和收益值得验证的可选读出，不强求每类覆盖 |

Intel 与 NVIDIA GPU 同为最高档；缺少实机时保留缺口，不降档或模拟验收。主线 P2 模型可先在 P1 硬件适配，P2 多设备协同先使用已适配设备、先单机再多机及复杂异构。优先模型所需的混合状态/编码器等最小组件随其完成，不等于整类 P3 模型提前；当前 Qwen 必要状态维护不被后移。

Windows 当前路径之外，Linux x86 与 P1 GPU 代表组合随优先硬件推进；PC NPU 必要主机接口随 P2 推进；ARM/macOS 普遍覆盖、移动系统及浏览器留后期。模型格式与架构、权重/激活/累加/状态精度分别登记；有同样后缀或上游可加载不能视为 Wllm 已兼容。远程 API 接入不计入本地执行支持，不静默转远程。

## 7. E5：公共适配与需求驱动选择

| 编号 | 内容 | 当前状态 / 产物 |
|---|---|---|
| E5-01 | CPU/物理设备/驱动、系统与设备容量、存储、后端操作能力探测 | 本机最小子集已实现，跨平台/设备与带宽等待补；数据有时间/来源，未知明确标记，设备/共享容量去重 |
| E5-02 | 硬约束、资源预算、用户目标和偏好模型 | 待实施；版本化需求契约，质量/模型/上下文是否允许变化分别表达，冲突与不可行原因可解释 |
| E5-03 | 可执行候选生成与筛选 | 待实施；只纳入已有实现且满足用户约束的操作，输出后端/线程/批量/放置/缓存等可复现计划及拒绝原因 |
| E5-04 | 有界调优、计量校准、候选选择与折中展示 | 待实施；静态规则起步再用测量校准，计选择成本；估算/实测分列，不宣称全局绝对最优 |
| E5-05 | 请求安全边界的计划调整、解释与回退 | 待实施；状态迁移先验正确，先在请求边界调整，记录生效版本/代价；不能静默更改用户硬约束 |
| E5-06 | 按用户三档执行跨设备/模型/操作验收 | 待实施；实机、模拟、功能、数值/质量、资源、稳定性、性能分项，弱硬件保留，无设备不记已验证 |
| E5-07 | 模型/任务/Reflex 读出/执行引擎/设备适配契约与能力登记 | 待实施；先做当前及 P1 所需最小子集，分别记录是否纳入、目标/实现/验证/收益，不要求先建完通用框架 |
| E5-08 | 各档模型与任务代表适配 | 待实施；主线全品类、Reflex 适用子集；锁许可/工件/处理器/模板/输出头/状态和参照，禁止以额外评估器补齐纯生成兼容 |
| E5-09 | 各档设备与专长执行引擎接入 | 待实施；先 x86/Intel/NVIDIA，后 PC NPU/内存存储/协同，再其余；锁工具链/版本，实际放置与枚举分开，计转换/编译成本 |

共享基座承担身份/配置、生命周期、资源账本、执行调度、取消/超时和计量；模型适配负责预处理、计算图、状态与输出；任务/Reflex 适配负责输出语义。接口设计不等于已提供通用插件系统；异步设备工作、回滚与释放须按底层真实能力逐项验证。

## 8. 近期交付顺序与依赖

近期仍以可复现的性能改善与可用推理为交付方向，同时推进 P1 代表适配。每轮选择有限子项，按以下关口准备，不批量实现所有研究候选，也不设未经资源验证的日期承诺。

| 推进关口 | 选择的任务与交付 | 进入下一实验的条件 |
|---|---|---|
| 先补对应基线 | E2-01/06、E3-07A，以及 E4-01/E5-01 最小预算：固定模型/负载、数值/质量/噪声门槛，补 CPU 与 Reflex 代表任务 | 得到可复现功能/质量参照和资源准入；失败如实记录。无需等全任务集验完才准备无依赖接口/诊断 |
| 并行准备最小实验 | E3-03/07C 完整状态 API 核查；E2-04 输出投影差异定位；E3-01/02 热点与成本调查；E5-07–09 的 P1 代表适配 | 每条线各自满足工件/接口/设备条件。NVIDIA 不依赖 Iris Xe 修复，算子不依赖 CPU 重排修复，普通 CPU/模型适配不依赖 MTP |
| 逐项性能交付 | 当前可行的 E2 参数/生命周期、E3 状态/算子/执行优化、E3-07B/E；按生成瓶颈准备 E3-04 接口 | 单项先过数值/任务质量与资源，再受控重复测量；C 正确后才做对应 D，推测需完整回滚/采样检查 |
| 扩大代表组合并验证组合 | P1 模型/硬件分别引入，E3-06 对已成立机制消融 | 新模型和新硬件尽量分步，避免差异无法归因；不继承其他设备/模式的结果，不要求所有 P1 型号完成才准备 P2 |
| 进入第二档任务与容量 | E4-02–07、PC NPU、协同与主线 P2 各任务的代表流水线 | 对应单设备/模型先可正确执行；容量/质量/延迟分别验收，Reflex 只取适用任务 |
| 持续完善策略与后期覆盖 | E5-02–06、P3 及按需多模型/wgp | 可先准备需求契约；自动选择只能使用已具备能力，完整系统不作为每项优化前置 |

明确依赖为：完整状态保存/恢复正确，分别支撑前缀/会话复用与推测回滚；共享批量须先验证其对应状态路径，不要求先交付完整前缀缓存才准备 MTP。另一条为 MoE 基本模型/路由适配 → E4-02 按需存取 → E4-03/04/05 缓存/分工/预取。Dense E4-06 与 MoE 线独立。单项成立后才能进入 E3-06 组合；公共预算检查不是完整容量系统完成的要求。

## 9. 研究候选、暂缓项与风险处理

参考项目按可借鉴机制进入任务，不按名字、论文倍数或新旧程度自动排序。本轮没有重新搜索/核实全部项目，也没有新增集成；版本、来源、许可证和局部适配成本继续由[统一研究池](engine-references.md)及[Reflex 研究](reflex-research.md)维护。

| 研究方向 | 原有参考入口举例 | 任务与边界 |
|---|---|---|
| CPU/量化/局部查表 | llama.cpp/ggml、ik_llama.cpp、FastLLM、llamafile、BitNet、T-MAC | E2-02/03、E3-01；保留目标权重语义验证。原生低比特模型是独立选项，不承诺把当前权重改成低比特后无损 |
| 后端/执行图/端侧 | SYCL/Vulkan/OpenVINO、OpenVINO GenAI、Lemonade、MLC/TVM、Splash、MNN、KleidiAI | E2-04、E3-02、E5-09；入口/版本/计算精度/状态能力分别检查，不能从同厂商或同格式外推 |
| 推测/MTP与回放 | llama.cpp speculative、DFlash、FreeToken、QuestWend、FastLLM、DeepInfer 等 | E3-04、E2-01/04/06；接口/工件/采样/状态先验，作者平台或集群成绩不是本机收益 |
| 状态/注意力/调度 | vLLM、SGLang、LMCache、FlashAttention、FLA、FlashInfer 等 | E3-02/03/05；精确路径、混合状态与操作组合分别验收，不默认引入所有平台依赖 |

| 决策策略/校准/协议 | LLM2Jev、SemIf、snapjudge、llamacpp-jev、Kev、jeff | E3-07A–G；直接标签、yes/no、树评分及 confidence 定义不互换，专用权重可选，不另立项目 |

保持关闭或暂缓：数值门槛未过的 CPU 重排/既往 AVX512/Vulkan 路径；无稳定收益依据的执行开关；不具备匹配工件/接口/回滚条件的 MTP/草稿集成；全模型穷举 SSD 查表、用地址变化代替主干运算的近期实施。局部查表算子仍可研究，不能把它等同模型输出穷举。

训练、剪枝、蒸馏不是隐含实施任务；没有匹配草稿时不擅自训练。GUI、HTTP、wgp、多模型常驻和多机服务没有变成当前必交付前置，具体按对应任务与后续需要进入。未来多设备目标保留，但不意味着此轮搭建集群。共享内存去重、存储容量与速度分验、后台负载和文件缓存控制、未知算力/带宽瓶颈是持续检查点。

## 10. 性能、质量与交付验收

### 10.1 必须分别报告的指标

| 维度 | 口径 |
|---|---|
| 启动/加载/编译 | 进程到就绪、权重读取、初始化、图编译及缓存冷暖；模型常驻不能伪装为首次启动 |
| 输入处理 | 实际新计算 token 与耗时；复用/逻辑 token 分列，不能把命中缓存的 token 当新计算吞吐 |
| 首 token / 首个正文 | 请求到首生成 token；有思考时另列首正文等待，保留思考与采样 |
| 持续生成 | 解码 token/s、间隔/抖动、有效目标输出，草稿/拒绝 token 另计；不能从整次耗时倒推 |
| 完整请求/会话 | 接收至完成/失败/取消，含排队、加载、预处理、回退、调度、同步及相应释放成本；固定步数与自然完成分组 |
| Reflex 决策 | 父请求/逐题/分支延迟、候选数、输入/复用/计算 token、前向次数、质量/拒答/校准与回退总成本；0 生成时不填解码吞吐 |
| 非文本任务 | 相应模态输入处理、首结果/完整结果延迟、任务吞吐与质量；记录分辨率、帧/音频长度及处理器配置，不强制使用 token/s |
| 资源/稳定性 | 工作集、进程提交、系统/设备分配、共享容量、缺页/I/O、启动/稳态峰值、失败与持续运行；峰值采样范围和未知项注明 |

### 10.2 每项交付的固定流程

1. 选择任务、代表硬件/工件/负载与用户约束，固定源码/依赖/模板/配置；设置实验前数值、质量、资源、噪声和允许回归边界。
2. 先功能、数值/质量、状态隔离/恢复、错误/取消与释放，再校准资源。资源不足的性能实验明确拒绝，不自动减少模型/上下文或关闭后台应用。
3. 关闭干扰剖析后做受控重复、交替/随机顺序对照；记录冷暖、输出长度、温度/供电/后台条件和原始样本。少量样本不宣称可靠 P99；现有 5% 筛选线不是通用“明显加速”产品承诺。
4. 同时展示各项速度、质量、内存及稳定性，不用单一综合数掩盖回归。正确性通过不等于快；数值未通过也不自动证明任务质量下降，但不足以默认采用。
5. 采用、专项保留或关闭/撤回；组合要消融，负收益留结论。只完成加载标“可加载”，功能成功标明负载；性能预期附假设，不填实测列。
6. 更新实现/验证/收益与限制，保存报告、可复现命令及工件身份，完成对应检查后按既有规则提交、推送并核对远端。模型、二进制、本机配置、原始提示/输出与日志不随文档发布。
