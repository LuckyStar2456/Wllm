# CPU 内存校准与 Vulkan 运行探测

日期：2026-10-21。本轮交付对应 E4-01/E5-01 的 CPU 有界内存校准、E2-01 三类单次试采样及 E2-04 独立核显路径探测。它们尚不构成稳定提速或完整 GPU 验收。

## 实现与绑定

- `--memory-diagnostic` 在上下文就绪、输入处理结束和上下文释放前查询固定 llama.cpp 的 `llama_get_memory_breakdown`；该接口位于 `llama-ext.h`，属于 WIP 接口，绑定依赖提交 `f2918cabbffe8abf8e2a90c1c089085fa116c2cf`。诊断运行不进入性能汇总。
- 常规记录增加 OS 进程生命期的工作集峰值与提交峰值；`process_peak_private_bytes` 取 Windows `PeakPagefileUsage`，不等于实际磁盘分页量。原有采样工作集峰值继续单列。
- `scripts/calibrate_memory.py` 运行三个独立 CPU 进程，保存缓冲分配与 OS 峰值。`scripts/memory_calibration.py` 要求完整三类观测、足够长输入、固定安全余量，绑定可执行文件、模型、负载清单的 SHA256，以及内存配置、CPU/总 RAM、依赖提交和 CPU 构建。更换构建、模型、配置或硬件须重新校准。
- `scripts/benchmark.py --memory-calibration PATH` 显式采用校准；默认仍用原静态账本。两份判断分别保存，每次初始检查、预热和样本前读取新的资源快照。准入不会修改模型、上下文、状态精度、思考或采样设置。

本机保持 Qwen3.5-9B 主文本 GGUF Q4_K_M、4096 上下文、F16 KV、F32 循环状态、思考开启、4/4 线程、batch 128、AVX2，重排/持久线程池/末批 logits 优化关闭。校准只覆盖这一 CPU 执行配置及当前负载清单，不适用于状态缓存、推测回滚、GPU 或通用跨设备选择。

## 实际分配与准入

| 内存诊断 | 输入 / 输出 token | 进程提交峰值 bytes | OS 工作集峰值 bytes |
|---|---:|---:|---:|
| 聊天 | 35 / 32 | 734564352 | 5255163904 |
| 代码 | 71 / 128 | 735875072 | 5261225984 |
| 长输入 | 3280 / 32 | 746520576 | 5294747648 |

三个阶段的后端模型缓冲均为 5518657536 bytes，上下文缓冲 186908672 bytes（178.25MiB），计算缓冲 142874144 bytes。映射缓冲大小不等于实测驻留量；工作集可能受系统页面管理影响，不能只用其较低观测替代完整权重预算。诊断输出在预定 token 数结束，只用于内存观测，不代表完整任务答案。

显式校准物理预算采用：整份文件 5530617760 + 实测进程提交峰值 746520576 + 固定规则余量 268435456 + 系统预留 1073741824 = **7619315616 bytes，约 7.096GiB**。提交预算为 2088697856 bytes。余量取 `max(256MiB, ceil(峰值/4))`；上下文与计算缓冲已包含在进程提交峰值内，不再重复相加。原静态 3GiB 工作区账本及约 9.325GiB 预算保留。此处降低的是估算不确定性，并未降低实际模型内存或证明分页消失。

第一次请求三轮完整基线时，可用物理内存约 6.788GiB，仍被校准门槛拒绝，预热/样本数均为零。后续独立构建及探测结束后，新的快照为 8141012992 bytes 可用物理内存，三类单次试采样得以开始。没有关闭其他应用、修改系统内存设置或静默缩小任务以通过门槛。通过准入仅表示可以采集，有限观测加安全余量不是所有输入与长时间运行的精确上界。

## 任务试采样

原始资料位于本地 `reports/calibrated-pilot-20261021/`；详细数值与最终状态见同名 JSON 报告。它是单配置、每类一次的流程检查，OS 文件缓存未受控，不能用于比较优化收益。

- 聊天解释：生成 768 token 后触及上限，预期为 EOS，未形成最终答案，判定失败并排除有效性能汇总。保留思考及原输出上限，不通过关闭思考或事后放宽完成条件把它改记成功。
- 代码生成：EOS 正常结束，680 输出 token。仅检查最终正文；按首次出现顺序去重、支持生成器、不排序/无依赖的实现和三个要求示例通过审阅，平均 O(n) 时间、O(k) 空间说明符合实现。对空输入、顺序、原列表不变、生成器、元组元素及 Python 相等语义共六项执行检查通过。这只代表一个公开构造题目。
- 长输入固定输出：完成 3280 输入、32 输出 token，按预定 `max_tokens` 正常结束；仅验收完整计算与计数，不把截断文本当完整任务质量证据。

聊天题失败意味着这套质量基线尚未就绪；另外三个未选入本次试采样的任务、真实用户样本、重复性能和持续负载仍待补齐。后续先固定能覆盖开启思考的完整回答预算与完成条件，再单独建立新负载版本，保留本轮失败。

## 独立 Vulkan 工具链与模型探测

原先缺少 Vulkan headers/import library/glslc，初次配置失败。随后从 LunarG 官方渠道取得 Windows SDK 1.4.363.0，安装文件 SHA256 `94a82d378f7a5e3e54c9db7d2fb7016af136e14ac0a18dbf0f2f67a36352d141`、大小 303082720 bytes，签名检查有效，签发对象 LunarG, Inc.。使用项目 `build/toolchains/` 中的 `copy_only=1` 本地工具链；安装前后用户/机器 PATH 和 VULKAN_SDK 一致。该方式的官方含义见 [LunarG Windows 入门文档](https://vulkan.lunarg.com/doc/view/latest/windows/getting_started.html)，版本/下载元数据来自 [官方 API](https://vulkan.lunarg.com/content/view/latest-sdk-version-api)。没有安装新显卡驱动。

`scripts/build_vulkan_probe.ps1 -VulkanSdk <本地SDK>` 验证依赖锁和 SDK 文件，仅为当前进程设置 SDK 查找路径并在退出时恢复，独立生成上游 `llama-bench` 与 `llama-simple`。本轮两者构建成功；默认 Wllm 的 Vulkan 开关仍关闭。

实际枚举一个 Iris Xe Vulkan 设备，UMA=1、FP16=1、BF16=0、矩阵核心未报告。接口报告的共享容量不加到物理 RAM。探测配置为当前模型、`-pg 32,16 -r 1 -t 4 -b 128 -ub 128 -ngl 2 -dev Vulkan0 -ctk f16 -ctv f16 -fa off --repack 0 -lm mmap`，退出码 0，完整进程墙钟约 29.781 秒。它证明小输入、两层放置的上游普通执行能运行。

该探测并非 Wllm 4096 上下文下的等价请求，不证明全部算子在 GPU 执行、完整放置、数值保真、生成质量、峰值内存、前缀恢复、推测回滚或稳定性。单次上游吞吐也不作为 Wllm 加速倍数；下一轮须先补同条件 CPU/Vulkan 数值、混合状态精度与取消/释放验证，再做重复全请求对照。SYCL/OpenVINO 本轮未实施。
