日期：2026-10-10。状态：已实现、已构建、已在本机运行验证；尚未取得用户实际使用验收，也未开展 E2 的系统性能优化比较。

## 交付与环境

- 入口：`scripts/run.ps1`；原生程序：`build/bin/Release/wllm.exe`；使用说明：[quickstart](../docs/quickstart.md)。
- Windows 11 / Intel i5-1135G7（4 核 8 线程）/ 约 15.70 GiB 物理内存。首版使用 CPU、4 线程、128 token 输入批次，不依赖 Ollama 服务。
- 用户最新默认：4096 token 上下文，可显式调整；输入不截断、不滑动上下文、不自动降低精度。默认保留思考与原模型采样配置。
- llama.cpp：`f2918cabbffe8abf8e2a90c1c089085fa116c2cf`；MSVC 14.44.35207 x64 / Release / CPU AVX2。原依赖源码未修改。
- 程序 SHA256：`2d1e7f26dc92b42a51aa326f8b47d20be8c15485a87c0817bd287c5569257ca6`。
- 环境快照：[environment.json](environment.json)，依赖锁定：[dependencies.json](../dependencies.json)。

## 模型身份与保真边界

- 原始文件 SHA256：`dec52a44569a2a25341c4e4d3fee25846eed4f6f0b936278e3a3c900bb99d37c`。
- 适配后文本容器 SHA256：`0f55ce3d5a059e9e84493ed0554d78b8634d5064efcc8dc0a910f283ecaf3c34`。
- 原 Ollama GGUF 只读保留。文本容器调整 KV 头数字段、位置编码字段和 SSM 偏置名称，排除内嵌视觉等非文本张量；427 个保留文本张量的类型、形状及原始数据 SHA256 全部一致，没有重量化。
- 这是同一模型的文本路径格式适配，不是换小模型。原清单约 9.7B 包含非文本部分，上游文本加载器报告约 8.95B；文件大小变化不计作引擎提速或参数档位成果。
- 适配依据为 [Ollama v0.35.1 官方兼容实现](https://github.com/ollama/ollama/blob/v0.35.1/llama/compat/llama-ollama-compat.cpp)，详细映射和校验由适配工具写入本地 `reports/model-adaptation.json`，不随仓库分发。
- 使用 GGUF 内嵌模板与上游 Jinja，已验证中英文提示词及分词入口。默认 K/V 缓存为 F16，关闭 Flash Attention 及额外 CPU 权重重排缓冲；没有通过降低权重或状态精度获得这些初始数据。

## 一次初始观测

输入为 `What is 1+1? Answer with one digit.`，22 个输入 token，默认 4096 上下文、思考开启、原采样参数，显式 seed=42、输出上限 512；实际在 EOS 自然结束。这是短输入冒烟验证，系统文件缓存未清空，不是冷盘性能基准。

| 指标 | 此次观测 |
|---|---|
| 加载至就绪 | 1.24 s |
| 输入处理 | 2.62 s / 8.40 token/s |
| 首 token 等待（含加载） | 3.94 s |
| 生成量 | 126 token，含思考 |
| 平均持续生成 | 5.07 token/s |
| 整次请求（含资源释放） | 29.52 s |
| 采样峰值工作集 | 4.89 GiB |

数据会随输入、后台应用、缓存、频率和供电变化。没有与同条件 Ollama 或最佳调优上游建立完整对照，不能宣称 Wllm 已加速多少倍。

## 当前限制与下一阶段

首版每进程一个文本请求，无 GUI/HTTP/多轮缓存/视觉/推测解码。4K 表示本次实际配置与分配预算，尚未完成接近 4K 的长文本任务质量评测；更大上下文允许配置但不保证本机可用。尚无长期稳定性、跨硬件或普遍质量等价结论。

下一阶段 E2 先固定真实工作负载、质量/回归阈值及同条件基线，再逐项比较线程、批次、加载与后端等候选；保留本版可运行路径。研究候选继续统一比较，不将所有候选集成设为下一版前提。
