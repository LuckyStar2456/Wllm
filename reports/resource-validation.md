# 最小资源账本与三类基线准备

日期：2026-10-21。基于 `6d42fb6` 的 Windows / i5-1135G7 / 16GB / Iris Xe / Qwen3.5-9B Q4_K_M，固定 llama.cpp `f2918cabbffe8abf8e2a90c1c089085fa116c2cf`。用户确认聊天、代码、长文三类都覆盖。本轮交付资源与评测工具、构造负载和有界回归，**没有新增默认提速机制、正式性能样本或 GPU 模型验收**。

## 实现与使用

- `wllm --resources PATH`：独立于推理后端的原生探测；可无模型运行，传配置时仅读取 GGUF 元数据。保留已有证据文件，拒绝与提示词/交互/生成诊断混用。
- `scripts/resource_ledger.py`：补充 Vulkan 枚举、有效 UUID/LUID 关联、磁盘空间及 PATH 工具线索；不推断模型算子或状态支持。
- 单序列预算现在显式包含 F16 注意力 KV、F32 卷积/循环状态；JSONL 记录分列循环状态精度、系统提交额度、进程累计缺页与 I/O。
- `scripts/benchmark.py`：初始、预热、每次样本前重新检查资源；不满足保守预算就保存 `resource_rejected`，不自动改变上下文、模型或精度。
- `scripts/inspect_workloads.py`：共享基准提示词构造逻辑，用原模型词表/模板核实输入长度；只加载词表，不生成回答。
- `scripts/build.ps1 -BuildDirectory build/resource-ledger`：在独立目录构建候选，原 CPU 可执行文件另存本地用于对照；验证后也已构建默认入口。

## 本机资源事实与估算边界

本轮快照显示 Vulkan 枚举出三条 Iris Xe 记录，具有相同 UUID。完整 `vulkaninfo` 输出的有效 LUID 分别匹配三个 DXGI 接口；因此按 UUID 归为一个物理 GPU 组，保留全部接口别名。未用型号或 PCI vendor/device ID 猜测去重；缺少强标识或发生标识冲突时保持未知。DXGI 另有一个软件渲染接口，不计为可用硬件 GPU。

DXGI 的每个 Iris Xe 接口报告约 7.85GiB shared-system limit，不能重复相加，也不能加到约 15.70GiB 的系统可见物理内存中。`QueryVideoMemoryInfo` 是探测进程的预算/使用量，不是全系统可用 GPU 内存，依据 [Microsoft API 文档](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/nf-dxgi1_4-idxgiadapter3-queryvideomemoryinfo)。

| 账本项目 | 本机记录 | 证据性质 |
|---|---:|---|
| 映射文件 | 5,530,617,760 字节 | 文件大小；不是实测驻留量 |
| F16 注意力 KV | 128MiB | 当前 4096 上下文、8 个完整注意力层的元数据估算 |
| F32 卷积/循环状态 | 50.25MiB | 24 个循环层、1 个序列、无回滚快照；按固定源码估算，与历史后端分配日志相符 |
| 工作区 | 3GiB | 既有保守预留，未校准为实测 |
| 系统余量 | 1GiB | 当前显式配置 |
| 前缀缓存、草稿、回滚快照 | 0 | 当前均未启用；不适用于将来的状态/推测实验 |
| 保守物理预算合计 | 约 9.32GiB | 同时存活上界，不是实际启动/稳态峰值 |

保留的资源快照当时可用物理内存约 6.96GiB，未达到上述 9.32GiB 预算；这个瞬时数值不固化为产品常量。普通推理与正式性能准入分开，资源拒绝不等于模型无法运行。本轮确实运行了下述有界正确性检查，但不将其耗时列入性能基线。

当前 CPU 构建的 Vulkan/SYCL/OpenVINO 均未启用；PATH 中发现 `vulkaninfo`，未发现 `glslc`、`sycl-ls`、`icx`，这只表示 PATH 观察，不证明所有 SDK/运行时不存在。内存有效带宽、存储物理吞吐/IOPS、工作区校准、编译峰值和 GPU 模型状态操作均未验证。

## 三类负载准备

`benchmarks/representative-workloads.json` 是作者构造的公开示例任务，不是用户真实聊天/代码/文档集。保留原思考、采样和 4096 上下文；模板检查得到：

| 任务 | 输入 token | 输出预算 | 验收方式 |
|---|---:|---:|---|
| 聊天解释 | 35 | 768 | 自然 EOS；人工核对事实与表达 |
| 聊天学习计划 | 52 | 1536 | 自然 EOS；人工核对完整性与约束 |
| 代码理解 | 102 | 1024 | 自然 EOS；人工核对 bug 和修复 |
| 代码生成 | 71 | 1024 | 自然 EOS；人工核对顺序、生成器和复杂度 |
| 长文事实提取 | 3039 | 768 | 自然 EOS，正文精确为 `7319`；仅有限事实提取 |
| 长输入固定输出 | 3280 | 32 | 固定 32 个输出 token；不作为完整回答质量验收 |

六项输入加完整输出预算均不超过 4096。这里只验证模板和长度，质量均未评估；新三类任务尚未运行生成。完整回答与固定输出样本不混算质量；没有自动答案判定的任务在基准结果中标记 `manual_review_required`。

## 已完成的验证

- 从独立的 `build/resource-ledger` 配置并编译应用与原生检查通过；默认 `build/` 入口也构建通过。最终原生检查 **31 项通过**。
- 资源检查 **9 项通过**：包括同 UUID 去重、相同 PCI 型号不误合并、有效 LUID 别名、冲突身份、探测不生成、不覆盖证据、超预算拒绝和基准在预热前停止。
- 基准聚合检查 **2 项通过**：失败/诊断样本不进入成功性能汇总。
- 默认入口的集成检查 **8 项通过**：模板/Unicode、默认思考完整回答、单 token、资源/上下文拒绝、超时、生成时取消、多输入批次及生成边界。
- 与旧 CPU 可执行文件对照：两个诊断输入，每个请求固定 seed 42、32 个输出 token；逐一比较最终 prefill 的完整 **248,320 维 logits**，最大绝对差异和 softmax KL 均为 **0**，token 序列和文本均一致。此结果只覆盖这些诊断样本，不替代完整任务质量、采样分布或性能验收。
- 实际调用三类基线工具，状态为 `resource_rejected`，**预热 0 次、正式请求 0 次**；模型哈希读取也在基准初始拒绝时跳过。报告中的模型 SHA256 是随后独立只读重算得到，与既有适配报告一致。

可复算摘要见[机器可读记录](resource-validation.json)。原始资源快照、诊断 logits、运行日志和负载检查文件留在本地 `reports/`，不随源码分发。进程缺页包含软缺页；累计 I/O 包含缓存与其他句柄传输，不能据此报告 SSD 物理字节或硬缺页。
