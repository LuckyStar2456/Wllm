# Iris Xe Vulkan 正确性筛选

日期：2026-10-21。用户要求先验证本机 GPU 正确性，通过后再与 CPU 比较实际性能。本轮完成了独立 Wllm Vulkan 实验入口和数值筛选，但候选未通过既有数值门槛，因此正式性能比较未执行，默认程序继续使用 CPU。

## 对照条件与实现

固定 llama.cpp `f2918cabbffe8abf8e2a90c1c089085fa116c2cf`、当前 Qwen3.5-9B 文本 GGUF Q4_K_M、4096 上下文、4/4 线程、batch/ubatch 128、F16 KV、F32 循环状态、思考开启、seed 42 及原采样参数。重排、持久线程池、仅末批 logits、FlashAttention 与额外 host op offload 关闭。GPU 放置开启相应 KQV offload，状态类型不变。没有更换模型、驱动或降低精度/上下文。

`scripts/build_vulkan_probe.ps1 -WllmValidation` 通过 CMake 的 `CMAKE_PROJECT_<PROJECT-NAME>_INCLUDE` 钩子加入独立 `wllm-vulkan` 目标，复用 Wllm 的 `src/main.cpp` 与锁定的上游库，无需修改 vendor 源码，也不改变默认 CPU 的 CMake 开关。已有上游 Vulkan 构建可增量复用；SDK 查找环境仍限于构建进程。

`--gpu-layers N` 默认 0。非零值只在独立实验构建可用；默认 CPU 程序明确拒绝。实验入口要求唯一 Vulkan 设备、明确层数且不超出模型可放置层数，缺设备或配置错误不静默退回 CPU。有效配置记录后端/层数，诊断额外确认实际 Vulkan 模型缓冲大于零。原生资源账本对 GPU 标记未校准并拒绝性能准入；CPU 校准工具及校准应用函数均明确拒绝任何 GPU 放置，不能把 CPU 的进程提交峰值当 GPU 驱动/设备总内存。

## 预设门槛及实际结果

沿用已有 CPU 跨指令集筛选阈值：完整词表逐元素 `atol=1e-3, rtol=1e-4`，原始 softmax KL 上限 `1e-6`。阈值在 GPU 实验前固定，并未根据结果放宽。它是本项目的保真采用门槛，不是对所有后端的通用误差标准。即使文本相同，也须独立通过 logits 与 KL。所有数字来自最终 prefill 的完整 248320 词表；本轮尚未验证每一步 decode logits。

输入为“你好，请简要解释质数。”，模板后 18 token，生成固定 32 token。配置预先包含短、多批次和长输入三个阶段，短输入失败便停止后续阶段及性能比较。

| 候选 | 最大绝对 logits 差 | softmax KL | 32 token / 输出 | 数值门槛 |
|---|---:|---:|---|---|
| `gpu_layers=2`，默认计算路径 | 0.171907306 | 4.94626284e-6 | 相同 / 相同 | 未通过 |
| `gpu_layers=2`，禁用 Vulkan FP16 计算 | 0.172787189 | 5.32866775e-6 | 相同 / 相同 | 未通过 |
| `gpu_layers=1`，仅输出层 | 0.085984707 | 1.69136160e-6 | 相同 / 相同 | 未通过 |

更高计算精度候选只向 GPU 子进程传入 `GGML_VK_DISABLE_F16=1`，KV 类型仍为 F16。诊断脚本清理子进程继承的 Vulkan 调优环境后记录显式设置，不更改用户/系统环境变量。最早一组原始探测未显式清理继承环境，最终构建复核使用受控环境；各次构建摘要与结果分别保存于结构化报告。

最终构建在受控环境复核两层默认配置，最大差和 KL 重现为 0.171907306 与 4.94626284e-6，32 token 仍相同。不是只依赖改动前实验程序的数据。

默认配置仍采用 CPU。GPU 的诊断计时、首次管线准备、输出层单次执行时间均未用于 CPU/GPU 性能排名；**正式性能样本数为 0，不能给出可信加速倍数**。文本相同的有限样本不代表完整任务质量、长上下文或混合状态正确性已验收。短输入失败后，本轮未扩展到长输入、完整放置、前缀恢复或推测回滚。

## 放置和差异定位证据

需要补充前轮小探测的层数口径：本固定修订把输出层计入 `n_gpu_layers`。日志确认 `2/33` 为输出层加一个 repeating layer；对应最后一个完整注意力层，不包含循环层。`1/33` 仅放置输出层。两层配置的实际 Vulkan 模型缓冲约 921.66MiB、Vulkan KV 16MiB，循环状态仍位于 CPU，日志保留 `R(f32)`、`S(f32)`。因此“小范围 Vulkan 可运行”不能扩大为循环层或完整模型已经通过 GPU 验收。

仅输出层也失败，说明该输入下不必经过 GPU 注意力或循环状态就能出现差异，下一步可优先构造最终输出投影的最小张量复现。源码存在计算路径差异：

- `ggml/src/ggml-cpu/ggml-cpu.c` 的 Q4_K/Q6_K 点积类型为 Q8_K，即 CPU 临时激活量化路径。
- `ggml/src/ggml-vulkan/ggml-vulkan.cpp` 的 MMVQ 分支使用 Q8_1，配合 `vulkan-shaders/quantize_q8_1.comp`；是否选择该分支取决于形状、设备和开关。
- 禁用 FP16 计算没有消除差异，不能仅归因于 FP16；本轮未捕获实际张量和每个管线选择，不能把上述源码差别直接认定为唯一根因，更不能推断为显卡或驱动故障。

后续应固定输出投影输入、Q6_K 权重和两侧临时激活，定位量化、点积或归约的首处分歧，再考虑保持既定模型/状态精度的修正方案。通过同一门槛后补多批次、循环层、长输入、完整答案和状态操作，然后独立校准 GPU 资源、执行交替重复全请求对照。性能须包含加载、首 token、prefill、decode、全请求、峰值内存及失败/取消；共享显存不能与 RAM 相加。

## 回归与记录

本轮 CPU 默认构建保持关闭 Vulkan；CPU 数值回归、原生/工具测试、GPU 入口拒绝及取消/超时检查的最终结果见 [vulkan-validation.json](vulkan-validation.json)。这些检查不改变 GPU 数值候选关闭的结论。原始记录、logits、提示词、生成文本、SDK 和二进制均留在本地 `reports/` / `build/`，只提交脱敏摘要。

- 原生 36 项检查及 Python 23 项数值/校准/资源/汇总测试通过。
- 默认 CPU 相对上一版的两个输入：完整 248320 词表 logits 最大差和 KL 均为 0，生成 token 及输出相同；独立 Vulkan 构建的 CPU 模式在同一短输入也与上一版 CPU 完全一致。
- 四项独立入口/生命周期检查通过：CPU 程序拒绝 GPU 请求、模型层数不隐式夹取、超时退出及记录结束事件、生成中取消及释放前分配观察。它们只验证进程终止/清理路径，不是重复会话、驱动内存泄漏或推测状态验收。
