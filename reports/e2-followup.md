# E2 后续：耗时剖析与长输入筛选

日期：2026-10-10。基于 `9d89de4`，设备、固定上游依赖和 Qwen3.5 Q4_K_M 权重不变。上下文 4096，4 线程、批次 128、F16 状态、原思考与采样设置保持不变。

本轮交付可关闭的阶段/算子剖析、扩展工作负载和候选验证工具。**没有新增默认启用的性能优化**：权重重排未通过数值门槛；跳过中间 logits 的单轮性能结果不稳定。保留上一轮已经交付的显式模型驻留模式。

## 剖析与候选依据

`-Profile` 分别计量输入计算、生成计算、采样、文本转换与输出，并在终端结束摘要及 JSONL 中显示。`-ProfileOps` 按阶段、算子和第一输入类型汇总诊断数据。二者默认关闭，驻留请求的统计独立重置。

阶段和算子诊断将 Q4_K 矩阵计算列为主要候选，本轮重点测试上游 AVX2 重排路径。最终构建的短输入复查中，15 次生成计算累计约 3.67 秒，16 次采样约 0.030 秒，文本转换和输出约 0.0007 秒，进一步支持优先调查模型计算而非采样或终端刷新。详细数据见[机器可读报告](e2-followup.json)。

算子回调会拆分计算图、同步并可能阻止融合，不能用其占比推断正常执行的精确算子占比。现有证据也未区分矩阵计算受算力还是内存带宽限制；没有硬件性能计数器、缓存缺失或带宽测量结论。

## 长输入与长输出

两种配置分别预热后串行运行，每个用例先基线、再开启 `prefill_last_only`，每种配置每个用例 **1 个样本**。关闭剖析、logits 导出和权重重排；使用相同 seed、输入、输出条件及新进程，不复用前缀。

| 负载 | 输入 / 输出 token | 输入处理：基线 → 候选 | 持续生成：基线 → 候选 | 请求耗时：基线 → 候选 |
|---|---:|---:|---:|---:|
| 长输入、固定输出 | 3378 / 16 | 289.55 → 241.93 s | 3.794 → 3.496 token/s | 295.68 → 248.66 s |
| 长输出、固定输出 | 49 / 128 | 4.61 → 4.52 s | 4.887 → 4.954 token/s | 32.75 → 32.22 s |
| 长输入、事实提取 | 3414 / 398 | 244.65 → 280.07 s | 4.117 → 4.077 token/s | 343.92 → 379.86 s |

六次请求均成功；三组对应生成 token 序列完全相同。事实提取两次均保留思考、自然 EOS，最终答案均为预设的 `7319`，没有以截断或提前结束替代完整回答。两种固定输出负载都达到约定 token 数。采样峰值工作集约 4.89–4.93 GiB，未发现整次峰值内存改善。

表中输出计入思考 token；请求耗时包含本次加载、输入、生成和模型释放，不含进程/后端初始化，不当作冷启动端到端耗时。

第一个长输入的输入处理单次减少约 16.4%，但生成速度降低约 7.9%；另一长输入的输入处理反而增加约 14.5%。电源方案为观察到的 ASUS Recommended，未调整系统设置；操作系统文件缓存、后台负载和温度/频率未受控，单轮顺序也无法排除偏差。因此这些值只用于筛选，不能宣称稳定提速、统计显著回归或冷盘性能；默认 `prefill_last_only` 仍为 false。

输入材料是重复事实及单个开头记录。这补充了长输入计算与有限事实提取证据，不构成真实文档、多位置检索、复杂推理或长期稳定性验收。

## 权重重排未采用

新增 `cpu_weight_repacking` 实验开关，默认 false。固定上游可为适用 Q4_K 张量选择重排缓冲，磁盘权重不变，但执行路径改变，必须单独验证数值。

沿用实验前声明的 `atol=1e-3`、`rtol=1e-4`、原始 softmax `KL<=1e-6`。第一个前缀的 248,320 个 logits 最大差异为 **1.5627069**，KL 为 **0.0005562684**，超过门槛。虽然 32 个 token 与正文相同，仍停止采用及后续性能评选；未放宽门槛。该诊断还观察到约 8.07 GiB 的采样峰值工作集。

开关只用于继续研究，启用时明确显示其未通过当前数值门槛。数值不满足基线容差不等于已经证明任务质量下降，但不足以作为用户默认配置。

## 复现与记录

最终 AVX2 构建通过，28 项原生检查、8 个原型集成用例、3 个新增剖析用例和 2 个基准汇总用例全部通过。剖析用例覆盖关闭/阶段/算子三条路径的完整 logits 和输出对照（最大差异均为 0）、超时部分记录、驻留请求统计重置及错误释放。16 token greedy 诊断与未修改的上游参考输出一致；此项不替代采样质量评测。

实际 PowerShell `-Profile -CpuWeightRepacking off` 入口运行成功，终端结束摘要显示各阶段数值。未通过的权重重排数值实验单独列为拒绝结果，不计入“通过”的测试数量。
