# 默认上下文扩展为 16K

日期：2026-10-21。按用户要求，当前默认上下文从 4096 改为 **16384 token**，包含输入与生成的总预算；仍允许显式覆盖。模型、主文本权重、Q4_K_M、F16 KV、F32 循环状态、思考、采样、线程和批次均保持原设置。

## 实现与配置

- `src/core.h`、命令行帮助、`configs/default.json` 和本机 `configs/local.json` 均同步为 16384；新模型准备流程仍复制仓库默认配置，已有其他机器的本机配置不会被自动覆盖。
- CPU 与独立 Vulkan 程序已重新构建；`run.ps1` 未传 `-Context` 时使用本机配置。GPU 校验脚本移除固定 4096，默认读取配置，可用 `--context` 显式复现历史设置。
- 资源账本按实际上下文重新计算，GPU 仍单独标记未校准；不自动降低上下文、精度或关闭思考。
- 旧 4K 校准绑定可执行文件与上下文，本轮构建和配置变化使其失效。历史报告及 4K 数值失败记录保留，不改写为 16K 结果。

## 实际分配与运行检查

16K 短输入 CPU 诊断中，三个生命周期阶段的上下文缓冲均为 **589561856 bytes（562.25MiB）**，计算缓冲为 158340704 bytes。对应注意力 KV 估算 536870912 bytes（512MiB），循环状态 52690944 bytes（50.25MiB）。相对 4K，KV 增加 384MiB，循环状态不随当前单序列上下文预算增长；缓冲分配不等于整个进程/系统的总驻留量。

原生 37 项配置/计量检查、23 项 Python 数值/资源/校准/汇总测试和 8 项本机集成检查通过。集成覆盖模板与默认思考完整答案、单 token 计数、输入/资源拒绝、超时、生成中取消、多批次输入及显式小上下文边界，不通过自动截断或滑动满足请求。

超过旧 4K 边界的容量样本已完成全部 **4217 输入 token、2 输出 token**，按预定 `max_tokens` 正常结束，配置为 16384、思考开启、CPU 原路径并启用分配诊断。完成状态及峰值见同名 JSON；该样本只验收完整输入计算、生成计数和 16K 上下文分配，不验收答案质量，也不是正式性能样本。短输入成功或预算增加都不等于完整 16K 长文质量已验证。

## 匹配负载与校准边界

新增 `benchmarks/context16k-workloads.json`，词表/模板检查结果为：聊天 35、代码 71、长输入 13048、超过旧边界样本 4217 token；各自包含预设输出预算后均在 16384 内。13048-token 长任务约覆盖 79.64% 上下文，可供后续有显式时间预算的内存诊断，但本轮只完成该任务的词表检查，没有执行完整推理或校准。

校准工具先检查长任务的实际 token 数，再执行内存诊断。使用原代表性清单时，3280-token 长任务不足 16K 的 70% 覆盖要求，实际验证在诊断前拒绝，`samples=[]`；不会运行后再降低验收条件或把旧数据放大。`--timeout` 支持显式调整长时诊断预算。新负载与旧负载清单摘要不同，校准和正式基准必须使用相同清单，不能相互冒充。

完整 16K 峰值校准、自然 EOS 的长文质量、持续稳定性与重复性能尚未验收。普通推理可运行和具备正式性能验收资源是两种判断；当前静态账本仍保留保守工作区与系统余量。

## GPU 正确性复核

独立实验程序在配置中的 16K 上下文下重新比较 CPU 与 Iris Xe 两层路径。短输入完整 248320 词表的最大绝对 logits 差为 0.1719073057，softmax KL 为 4.94626284e-6，32 个生成 token 及输出相同；仍未满足既有 `atol=1e-3, rtol=1e-4, KL<=1e-6` 门槛。因此 GPU 配置继续关闭于默认路径，正式 CPU/GPU 性能样本为 0，不宣称 16K 已解决原数值差异。循环层、完整放置、前缀恢复及推测回滚不由此获得验收。
